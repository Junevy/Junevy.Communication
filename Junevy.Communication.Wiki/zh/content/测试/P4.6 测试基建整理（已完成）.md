## 做了什么

把 P4 记下的 S7 / FINS / MELSEC 三方重复的测试脚手架收进共享测试库 `Junevy.Communication.Testing`，并把 MELSEC 测试里的等价工具换成共享版本。

### 四个助手各自的用途与形状

| 助手 | 解决 | 形状 |
|---|---|---|
| `Polling.WaitUntilAsync(Func<bool>, int ms = 10000)` | 7 份手写轮询循环 | 5 ms 间隔轮询，用 `Stopwatch` 计时；**超时抛异常之前仍做最后一次判定**——否则"最后一刻才变成 true"的合法情况会被误判为超时 |
| `Arrival.WithinAsync(Task<T>, int ms)` / `WithinAsync(Task, int ms)` | F10 | `Task.WhenAny` + 超时即失败；处理 `Task`（无返回值）与 `Task<T>`（返回值）两种，避免用 `Task.CompletedTask` 兜底 |
| `LoopbackTcp.Client(port)` / `Reconnecting(port, …)` / `WithHeartbeat(port, …)` | F6、F10 | 三个独立的静态工厂（不能链式调用），各自返回一个新的 `127.0.0.1` 上的 `TcpClientChannelConfig`：只有端口、再加重连、再加心跳与重连。S7 用 102、FINS 用 9600、MELSEC 用其标准端口，三方的 host/port 字面量与心跳/重连选项装配都不再各写一遍 |
| `PlcByteMemory` | F7 | 按 `(区名, 块号)` 分块的**线程安全**字节存储。`Define(area, block, length)` 新建全 0 的块并返回存储本身；`Block(area, block)` 取已定义块的存储供用例预置与核对；`TryRead` / `TryWrite` 返回 `PlcByteAccess.Ok` / `NoSuchBlock` / `BeyondEnd` 三态。**写失败时块一个字节都不变。** 区名区分大小写 |

## 刻意不做的

- **`PlcMemory` 的内部**：P4 笔记里 F7 的建议是"`PlcMemory` 保留字粒度 API 并改为 `PlcByteMemory` 之上的视图"。**没做**——`PlcMemory` 已被 5 个 Melsec 用例文件依赖，`TestingKitTests` 还在断言它现有行为，动它的公开面等于动 MELSEC 测试的既有契约，而 P4.6 的规矩是"断言不改"。两个内存并存：字粒度用 `PlcMemory`，字节粒度用 `PlcByteMemory`。
- **钩子测试门面**（F5）：与 P4 的决定一致，仍然不做。协议钩子继续经"已连接的客户端 + 替身"测试，代价是纯算术的期望也要拖着通道、会话与应答替身（FINS 的 `FinsClientHooksTests` 里 16/22 个用例如此）。
- **`ScriptedByteChannel.SendAsync` 的既有行为**：它一直会把出站帧记进 `Requests`。P4.6 只给它加 `LastRequest`（**只在 `RequestAsync` 更新**），没有顺手改 `SendAsync`。
- **Modbus 测试与 Channels 测试自带的同名工具**：`Modbus.Tests/ParserCorpus.cs` 自带 `Hex`、`Channels.Tests/TestSupport/LifecycleFakes.cs` 自带 `FakeByteChannel`，两者形状不同且不在本计划范围，均未动。

## 过程中被测试抓出来的问题（存档价值）

- **FINS 位掩码的真实缺陷**：迁移 `FinsEndToEndTests.BitReadsCoverWholeWords_AndNativeBitWritesContinueIntoTheNextWord` 时失败——期望 `[0xC000, 0x0003]`，实际 `[0x8000, 0x0003]`。根因是把位掩码写成 `1 << (absoluteBit % 16)`，**字节只装得下 8 位**，`(byte)(1 << 14)` 截断成 0，位 8–15 的写入静默丢失。改正为字节内的位号 `absoluteBit % 8`。这个缺陷是既有断言抓出来的。
- **`FinsDeviceSimulator` 一度涨到 317 行**：拆出 `FinsSimulatorMemory`（132 行）后回落到 223 行，同时"字节布局与存储"和"帧翻译"分成两个职责。
- **变异检查**：`PlcByteMemory` 把"正好到块尾"判为 `BeyondEnd` → 8 个用例失败；写失败时仍修改块 → 2 个用例失败。均证明测试真的钉住了这两条。
