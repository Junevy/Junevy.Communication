# S7 协议（S7comm over ISO-on-TCP）

> 代码基线：`Junevy.Communication.Siemens`（net472;net8.0，`1.0.0-preview.1`，P4）。依据：西门子 S7comm 的公开线路资料与 RFC 1006（ISO-on-TCP），逐字段拼出计划第 17.1 节的黄金向量 V-S7-1…V-S7-12。**未经真机验证**（P4-D20）：所有结论来自手册与公开抓包，只在替身 CPU 上跑通过。与代码冲突时以代码为准；设计差异见设计文档第 20.5 节。

## 支持范围（P4-D1、P4-D2）

- CPU：S7-1200、S7-1500。S7-300 / 400 / 200 SMART / LOGO! 只是连接参数不同，本期不测试也不宣称支持。
- 传输：ISO-on-TCP（RFC 1006），端口 102，字节流交付。不做 S7comm-plus（符号访问、优化块）、UDP、串口。
- 区域：`DB`（数据块，0x84）、`M`（位存储，0x83）、`I`（过程输入，0x81）、`Q`（过程输出，0x82），全部按字节寻址（`PlcAddressUnit.Byte`）。
- 服务：Read Var `0x04`、Write Var `0x05`，每个请求只含 1 个数据项（P4-D12）。
- PLC 侧设置（不是客户端设置）：TIA Portal 中 CPU 的"连接机制"要允许 **来自远程对象的 PUT/GET 访问**；要读写的 DB 必须**取消勾选"优化的块访问"**（否则绝对地址 `DB1.DBW12` 无意义）；端口为 102。这两项没做时表现为 `0x8104` 或数据项返回码 0x03 / 0x05 / 0x0A，客户端会在消息末尾附上检查提示。

## 帧结构

三层外壳，从外到内：

| 层 | 内容 | 代码 |
|---|---|---|
| TPKT | `03 00` + 2 字节大端总长（**含 TPKT 自身**） | [Framing/S7Framing.cs](file://Junevy.Communication.Siemens/Framing/S7Framing.cs)：长度字段偏移 2、宽 2、修正值 −4，最大帧长取默认 65536 |
| COTP | 连接请求 CR `11 E0 …` / 连接确认 CC `11 D0 …`；数据传输 DT `02 F0 80` | [Protocol/CotpFrames.cs](file://Junevy.Communication.Siemens/Protocol/CotpFrames.cs) |
| S7 | 协议号 `32`、ROSCTR（1 = Job、2 = Ack、3 = Ack-Data）、保留 `00 00`、PDU 引用号 2、参数长度 2、数据长度 2；ROSCTR 为 2 或 3 时再加错误类、错误码各 1 | [Protocol/S7Message.cs](file://Junevy.Communication.Siemens/Protocol/S7Message.cs) |

PDU 长度从 S7 头开始计，不含 TPKT 与 COTP。读请求的地址项为 `12 0A 10` + 传输尺寸 + 数量（2 字节）+ DB 号（2 字节）+ 区域（1 字节）+ 地址（3 字节），共 12 字节，参数块合计 14 字节；应答的数据项头 4 字节（返回码、传输尺寸、2 字节长度）。传输尺寸：请求侧 BIT `0x01`、BYTE `0x02`；应答侧 BIT `0x03`（按位）、BYTE/WORD/DWORD `0x04`（按位）、OCTET STRING `0x09`（按字节）。常量与换算在 [Protocol/S7VarItem.cs](file://Junevy.Communication.Siemens/Protocol/S7VarItem.cs)。

- **地址字段是位地址**：字节号 × 8 + 位号。`DBW2` → `0x10`，`DBX10.3` → `0x53`，`MB10` → `0x50`。
- **应答数据为奇数长度时不补填充字节**；多项请求才需要填充，本期只做单项。
- PDU 引用号来自进程级 16 位单调计数器（Core 的 `Junevy.Communication.Core.Utils.SequenceCounter`，挂在 [Protocol/S7Message.cs](file://Junevy.Communication.Siemens/Protocol/S7Message.cs) 上的 `S7Message.PduReferences`），客户端请求与握手、心跳探测共用；应答必须回显同一引用号，否则 `ProtocolViolation`（P4-D8）。

## 握手与会话（P4-D9、D13）

`ConnectAsync` 在 TCP 连通后依次执行三步，都在 [S7Handshake.cs](file://Junevy.Communication.Siemens/S7Handshake.cs)（`IConnectionInitializer`）里：

1. COTP CR：本地 TSAP `01 00`，远端 TSAP = `(ConnectionType << 8) | (Rack << 5) | Slot`（默认 PG、Rack 0、Slot 1 → `01 01`，P4-D19）。只校验应答的 `D0`。
2. Setup Communication：请求 PDU 长度**固定 960**，不提供选项；S7-1200 通常应答 240，S7-1500 应答 960。
3. 协商值写入不可变会话快照（[S7Session.cs](file://Junevy.Communication.Siemens/S7Session.cs)，`Volatile` 整体替换引用），钩子读当前快照。**协商值小于 64 时握手失败，返回 `ProtocolViolation`。**

每次重连都会重新握手，`NegotiatedPduSize` 随之更新；握手之前它和包上限都不可用，此时操作返回 `Unspecified`，消息 `The S7 packet limits are unavailable because the Setup Communication handshake has not run on this channel.`（这正是"绕过 `S7Client.Create` 自己搭通道"会撞到的错误）。

## 地址（P4-D16）

| 写法 | 含义 | 备注 |
|---|---|---|
| `DB1.DBX12.3` | 数据块 1 的第 12 字节第 3 位 | `X` 必须带位号 |
| `DB1.DBB12` / `DB1.DBW12` / `DB1.DBD12` | 数据块 1 第 12 字节起的 1 / 2 / 4 字节 | `B` / `W` / `D` 禁止带位号 |
| `M12.3`、`MB12`、`MW12`、`MD12` | 位存储区，同上 | I、Q 区同形状（`I0.0`、`QW2`） |
| `%DB1.DBW12` | 带 `%` 前缀 | 可选；大小写不敏感；数字一律十进制 |

> [!warning] 注意：I、Q、M 区不接受 `X` 宽度字母
> `MX0.0`、`IX0.0`、`QX0.0` 会被拒绝（`InvalidRequest`，消息 `... the width letter must be B, W or D.`），位地址请写 `M0.0`、`I0.0`、`Q0.0`（或带 `%`）。只有数据块用 `X`：`DB1.DBX0.0`。
> 这是 P4-D16 的既定语法。P4 验收时执行者提出 TIA Portal 有时会显示 `MX0.0`，但未经确认；用户 2026-10-12 决定**保持现状、不支持**。若现场配置表里出现 `MX` 写法，宿主应在导入时改写为 `M`，或先用 `IPlcClient.ParseAddress` 校验后提示用户。

宽度字母**不限制**读写长度——长度由调用的方法决定（`ReadInt16Async("DB1.DBB0")` 合法）。范围集中在 [S7AddressParser.cs](file://Junevy.Communication.Siemens/S7AddressParser.cs) 校验：DB 号 1–65535、字节号 0–2097151（24 位地址字段）、位号 0–7；非法文本的消息为 `'<x>' is not a valid S7 address: <reason>.`，空串为 `The address is empty.`。跨过的末字节超出 2097151 时 `ValidateRange` 返回 `InvalidRequest`：`The access on '<x>' ends at byte N, beyond the address field limit 2097151.`。末字节按粒度计算：字每点 2 字节、字节每点 1 字节，写位按绝对位号换算（`M2097151.6` 起写 2 位合法，起写 3 位越界）。

声明式软元件表在这里不够用（`DB1.DBW12` 有两个数字），因此 S7 自写解析器；`S7Device` 仍实现 `IPlcDeviceDefinition` 以保持 `PlcAddress.Device` / `Unit` 的语义，但它的 `Symbol` / `Radix` 不被解析器使用（计划 20.2 节 F1）。

## 单包上限（P4-D12）

| 协商 PDU | 读字节 | 写字节 | 读字 | 写字 | 位 |
|---|---|---|---|---|---|
| 240（S7-1200 常见） | 222 | 212 | 111 | 106 | 每请求 1 位 |
| 960（S7-1500） | 942 | 932 | 471 | 466 | 每请求 1 位 |

读 = PDU − 18（应答头 12 + 参数 2 + 数据项头 4），写 = PDU − 28（请求头 10 + 参数 14 + 数据项头 4），字数取字节数的一半向下取整。写位的上限为 1 是因为写位用 `0x03`（长度按位），单项只写一位。**写入上限 `PDU − 28` 是按字段推导的，Snap7 用更保守的 `PDU − 35`（P4-D20 ②）。**

## 数据格式与字符串

- 默认字序 `ABCD` + ASCII 字符串（P4-D11）。CPU 本身是大端：16 位是 `AB`、32 位是 `ABCD`，规范化布局等于设备内存的字节顺序，因此按内存顺序取字节即得到正确文本，类型化的多字值不需要重排。
- 套件的 `ReadStringAsync` / `WriteStringAsync` 按内存字节读写，适合 PLC 侧用 `STRING` 但只当作字符数组的场景。
- S7 的 `String` / `WString` 是**带长度头部的格式**，由 [S7StringExtensions.cs](file://Junevy.Communication.Siemens/S7StringExtensions.cs) 提供：`ReadS7StringAsync(address, maxLength)` / `WriteS7StringAsync(address, value, maxLength)`（头部 2 字节 = 声明的最大长度 + 实际长度，字符按 `PlcDataFormat.StringEncoding` 编码，`maxLength` 1–254）、`ReadS7WStringAsync` / `WriteS7WStringAsync`（头部 4 字节 = 两个 16 位大端字段，字符固定 UTF-16 大端码字对，`maxLength` 1–16382）。**写入只发头部与实际字符，字段余下的字节由设备保持原值**；读取取整个字段后按头部的实际长度截断，头部长度大于声明的最大长度或大于传入的 `maxLength` 时为 `ProtocolViolation`；值装不下或 `maxLength` 越界是 `InvalidRequest` 且不发请求。布局与常量在 [Protocol/S7StringFormat.cs](file://Junevy.Communication.Siemens/Protocol/S7StringFormat.cs)。
- 位写是原生的：`S7Client` 覆写 `CanWriteBitsNatively` 为 `true`，写位走 Write Var 的位访问（请求传输尺寸 `0x01`、数据项 `0x03`、长度 1 位，V-S7-9），套件不读回原值，也不看 `AllowReadModifyWriteBits`。每个请求只写 1 位，多个位拆成多个请求；跨字节时后面的点落到下一个字节（从 `DB1.DBX0.7` 起写 2 位，第二位是 `DBX1.0`）。
- 位读：读取覆盖这些点的字节再取位，从地址的位号起数，第 i 点在第 `(位号 + i) / 8` 个字节的第 `(位号 + i) % 8` 位（位 0 是字节的最低位）。

## 错误映射（P4-D14）

| 情况 | 结果 | 消息 |
|---|---|---|
| 应答头错误类与错误码非 0 | `RemoteError`，`ProtocolErrorCode = class << 8 \| code` | `S7 error class 0x81 code 0x04.` |
| 数据项返回码不是 0xFF | `RemoteError`，`ProtocolErrorCode` = 返回码 | `S7 item return code 0x05 (invalid address).` |
| 上述两类中的 0x8104 与返回码 0x03 / 0x05 / 0x0A | 同上 | 消息末尾附加 `Check that PUT/GET access is permitted in the CPU protection settings and that the data block does not use optimized block access.` |
| 头长度、TPKT、ROSCTR 或引用号回显不符 | `ProtocolViolation` | 指出实际与期望的字节 |

不做错误码说明表（P2-D12）：错误类与返回码的名称只用计划 17.3 节列出的那些（0x01 hardware fault、0x03 accessing the object not allowed、0x05 invalid address、0x06 data type not supported、0x07 data type inconsistent、0x0A object does not exist），其余含义依具体机型手册查。

## 心跳与重连（P4-D15）

`HealthProbeFactory` 在 [S7ReadProbe.cs](file://Junevy.Communication.Siemens/S7ReadProbe.cs)：读 `MB0` 的 1 个字节，只要收到格式正确的应答就算健康（返回码与错误类不参与判定——回了话就说明链路与协议栈正常）。TCP 字节流在请求超时后由通道重建连接并重新握手，因此重连会重新协商 PDU 与重新分配引用号作用域。

## 未验证项（P4-D20）

1. `0x8104` 对应"PUT/GET 未开启"是社区经验，不是西门子官方文档——所以提示语只挂在该组合上，消息本身仍只报原始码。
2. 写入上限 `PDU − 28` 按头部字段推导；Snap7 使用更保守的 `PDU − 35`。

两项都写在 README 与代码注释中，待真机验证。
