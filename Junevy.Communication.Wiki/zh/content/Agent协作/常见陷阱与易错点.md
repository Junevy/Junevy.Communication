## 1. 旧 API 名陷阱（重命名前名称全部不存在）

1.0.x 破坏性重命名（细节见 [[变更与决策/版本历史与破坏性变更]]）。训练数据/旧文档/旧代码里的这些名字**必须替换**：

| 错误（旧/猜测） | 正确（当前） |
|---|---|
| `ModbusTCP` / `ModbusRTU` | `ModbusTcpClient` / `ModbusRtuClient` |
| `ModbusTCPConfig` / `ModbusRTUConfig` | `ModbusTcpClientConfig` / `ModbusRtuClientConfig` |
| 命名空间 `...Modbus.TCP` / `...Modbus.RTU` | `...Modbus.Tcp` / `...Modbus.Rtu` |
| `ReadTimeOut` / `WriteTimeOut` | `ReadTimeout` / `WriteTimeout` |
| `request.Start` / `request.Length` | `request.StartAddress` / `request.Quantity` |
| `config.IntervalTime` | `config.FrameReadInterval`（RTU 专属） |
| `SetPort(502)` | `Port` 是普通可写属性（`config.Port = 502;`） |
| `CheckConnection()` | `IsConnected` 属性 |
| `ConnectAsync(host, port)` | `Connect()` / `ConnectAsync()` 用 config 的 Address/Port |
| NModbus 式 `ushort[]` 返回 | `ModbusResult<ushort[]>`——数据在 `.Data` |
| `ToUshort(low, high)` | 已删除，用 `BinaryPrimitives` / `ToBigEndian()` |

## 2. 错误处理三不要

- **不要**只读 `ErrorMessage` 做逻辑分支——先 `IsSuccess`，决策用 `ErrorKind`。
- **不要**对 `ErrorKind == ModbusException` 自己写重试——从站异常是权威答复，库已保证不重发。
- **不要**假设失败会抛异常——结果式 API 不抛通信异常；反过来，**也不要**假设全不抛：扩展方法参数错误抛 `ArgumentException`，Dispose 后调用抛 `ObjectDisposedException`。边界见 [[行为契约/错误处理与错误分类]]。

## 3. 请求对象约定

- `request.ProtocolType` 对传输调用**无意义**（客户端用自己的协议，帧构建以显式参数传入）；它只被裸帧 API `ModbusHelper.BuildRequestFrame` 读取。
- TCP 的 `TransactionId` 由库自增回写——传输调用**不要**手动赋值；手动赋值只对裸帧 API 生效。
- 0x08 / 0x17 的 `Data` 有专用布局（不是裸负载），见 [[API参考/数据模型]] 的 Data 布局表。
- 库不修改请求的协议语义字段；唯一回写是 TCP TID。

## 4. 工厂使用

- `GetOrAdd("key", cfg)` 已有同名 key 时**忽略新 cfg** 返回旧实例——改配置要先 `TryRemove` 再 GetOrAdd（或 TryAdd 前判重）。
- `GetOrAdd`/`TryAdd` 会**改写传入 config** 的零值/非法字段（回填默认）——复用同一 config 实例注册多连接时注意观察副作用。
- `Count` 只数物理实例，`Keys` 含别名；`RemoveAlias` 删不掉主条目（防误删，返回 false 且注册表不变）。
- ⚠️ `TryRemove(主键)` 会**连带删除所有指向它的别名并释放实例**（2026-10-07）。想保留别名就别删主键——旧版"保活实例"会造成实例既不释放也不可达的泄漏。
- ⚠️ `RegisterAlias` 在目标键不存在、别名键等于目标键、别名键已存在时都返回 `false`（不留悬空别名）。别名必须在目标键注册**之后**创建。
- Dispose 工厂 = Dispose 全部连接；容器托管时跟随容器生命周期，手办时记得关。

## 5. 连接行为

- `Reconnect=true` 时 **`Disconnect()` 后的下一次请求会静默重连**——想保持断开必须 `Reconnect=false`。
- `Reconnect` 是**懒**机制，没有后台保活线程；`IsConnected` 为 true 不保证下一次请求不超时。
- ⚠️ `Reconnect=false`（默认）时，超时/连接关闭/发送失败**立即返回、不重试**，真实 `ErrorKind` 保留（不再被覆盖成 "Not connected"）。想自动恢复必须显式 `Reconnect=true`——`RetryCount` 单独调大只会空转。
- TCP 收到 `ProtocolViolation` 也会**销毁连接**（2026-10-08），避免残帧污染下一次请求；需要继续复用连接的场合请设 `Reconnect=true`。
- RTU 不按 `ErrorKind` 销毁连接（TCP 会），所以 RTU 的 CRC 错等失败即使 `Reconnect=false` 也照 `RetryCount` 重试——两协议语义不同，测试/模拟时注意。
- 每连接一次一个请求；并发请用多实例。
- ⚠️ `Dispose()` 会**等在途请求退出**，因此可能比"立刻返回"慢；它不会抛异常中止在途请求，而是让它以 `ConnectionClosed` 结束。`Dispose` 之后再调 `Request`/`Connect` 抛 `ObjectDisposedException`，`Disconnect` 是空操作。
- `ConnectAsync(ct)` 用户取消抛 `OperationCanceledException`（不是返回 false），连接失败/超时才返回 false。

## 6. 语义细节

- 地址是**协议级零基**地址：PLC 编程软件里的 "40001" 对应线上地址 0（40001-40001），换算错误是最常见的现场问题。
- `Quantity` 单位随功能码：线圈按**位**（1–2000）、寄存器按**个**（1–125）。
- `WriteSingleCoil` 的 true 在线上是 `0xFF00`，不是 `0x0001`。
- 写类扩展方法返回的 `Data` 是**回显 PDU**，不是你写的数据。
- RTU `FrameReadInterval`（默认 30ms）影响多帧轮询吞吐；同步 `Request` 内部有 `Thread.Sleep`，别在 UI 线程调。
- TCP 的 `ReadTimeout` 是**收满整个响应帧的总时限**（同步异步一致）；RTU 的 `ReadTimeout` 只约束单次 Read 阻塞，慢从站调大它。

## 7. 平台差异

- net472：读/写与**连接**都靠关闭套接字中断，因此取消同样即时生效；`Task.WaitAsync` 与 `Socket.ConnectAsync(ct)` 不可用，分别用 `FromAsync + WhenAny` 与 dispose-socket 回调替代。net8.0：全程即时。
- TCP/RTU 读超时（异步）与用户取消都通过 linked CTS 区分，错误归类分别是 `Timeout` / `Cancelled`。
- ⚠️ `Socket.ReceiveTimeout`/`SendTimeout` **只管同步调用**——不要因为设置了它们就以为异步路径也受约束（2026-10-07 前异步路径确实没有任何时限）。
- ⚠️ net472 上销毁一个正在挂起读的套接字会产生 abortive close，对端收到 `IOException`/reset 而非干净 EOF；net8 上是干净 FIN。两者都表示连接已被拆除，排查"对端为什么报连接重置"时别误判成泄漏。
- Modbus 测试项目只有 net8.0——net472 分支无自动化覆盖，改条件编译要人工双目标编译验证（用 scratch 控制台项目同时跑 net8.0 与 net472 两个 TFM）。通道族的测试项目是双目标，见 [[测试/测试工程与验收方式]]。

## 8. 通讯通道族（P1）排坑

新增于 2026-10-10，适用于 Core、Channels、Tcp、Udp、Serial。行为细节见 [[行为契约/通道重连心跳与超时]]，内部结构见 [[架构设计/字节通道族内部结构]]。

### 类型与接口

- **`IsConnected` 只在 `IConnectable` 上**。`IByteChannel` 不声明它；`ITcpSession` 自行声明。两处同时声明会让经 `IClientChannel` 的访问报 CS0229（计划第 20 节 Task 3）。
- **`IClientChannel` 与服务端会话是两套类型**。`TcpServer` 与 `ITcpSession` 不实现 `IClientChannel`，不能放进 `ChannelFactory`。
- **`TcpServer` 不进工厂**（D17）。服务端由宿主直接 `new` 并持有，`Dispose` 由宿主负责。
- **`ChannelFactory.GetOrAdd` 同名已存在时忽略新配置**，返回已注册实例。改配置要先 `TryRemove`（与 Modbus 的 `GetOrAdd` 相同）。
- **找不到配置类型对应的创建器时抛 `NotSupportedException`**，不是 `ArgumentException`；同一配置类型注册两个创建器时在构造 `ChannelFactory` 时抛 `ArgumentException`。

### 配置与对象

- **`Config` 返回构造时传入的对象本身**，但运行行为只读构造时的快照。运行中修改 `Config` 的字段不会生效，需要重建通道。
- **配置非法时抛异常，不回填**（D5）。与 Modbus 的 `GetOrAdd` 回填不同，通道族不会改写调用方的对象。
- **基类与派生类的默认值不同**：`ClientChannelSettings.ResetOnRequestTimeout` 默认 `false`，`TcpClientChannelConfig.ResetOnRequestTimeout` 默认 `true`。派生的自定义字节流通道不会因请求超时断开，除非显式设置。
- **服务端 `ChannelComponents.HealthProbe` 构造即抛 `ArgumentException`**。同一个探测实例不能绑定到多个会话，改用 `ChannelComponents.HealthProbeFactory`（服务端每个会话调用一次，参数为该会话）。
- **需要引用通道的客户端探测不要构造后 `Bind`**（扩展性预演中的变通写法）。改用 `ChannelComponents.HealthProbeFactory`：它以通道自身为参数，在第一次成功打开、启动心跳之前调用一次，结果跨重连复用；工厂抛出或返回 null 使该次打开失败（`Unspecified`）。`HealthProbe` 与 `HealthProbeFactory` 互斥，同时设置构造即抛 `ArgumentException`（20.1 第 39、40 项）。
- **`Keyed` 模式的 `RequestAsync` 忽略 `RequestOptions.Matcher`**，按关联键匹配。`ReceiveAsync` 在所有模式下都使用 `Matcher`。

### 分帧

- **`Delimiter` 的 `MaxFrameLength` 只计分隔符之前的内容**。`KeepDelimiter=true` 时交付的帧最长为上限加分隔符长度。`IdleGap` 只在缓冲超过上限时抛出，恰好等于上限的帧可以交出。
- **`AppendDelimiterOnSend` 默认为 `true`**，发送 `Delimiter` 帧时会追加 `Delimiters[0]`。不要把分隔符写进负载，否则会出现两个分隔符。
- **`IdleGap` 的默认静默时间为 20 ms**。USB 转串口芯片的延迟计时器（FTDI 默认 16 ms）必须小于它，否则一帧会被切成两帧（设计第 8 节）。
- **`FrameCodecFactory.Create` 与 `ByteSequenceParser.Parse` 的 `hex:` 前缀**：`hex:0D 0A` 是字节，`0D 0A` 是 ASCII 文本。

### 超时与心跳

- **`Dispose` 不排空，`DisconnectAsync` 排空**。`Dispose` 立即释放，已收到但未派发的帧会丢失（计入 `FramesDropped`）。需要不丢帧时先 `DisconnectAsync`。
- **同步 `Dispose()` 最长等待 `DisconnectTimeout + 1000` ms**（服务端为 `StopTimeout + 1000` ms）。超时后释放在后台继续。
- **在 `FrameReceived` 处理器内调用 `DisconnectAsync` 或 `DisposeAsync` 不会排空队列**。派发上下文中队列剩余的帧直接计为丢弃。不死锁，但会丢帧。
- **UDP 与串口的内置心跳必须配置 `ExpectedReply`**（没有自定义 `HealthProbe` 或 `HealthProbeFactory` 时），否则构造即抛 `ArgumentException`。UDP 写入几乎总是成功，"发送成功即健康"检测不到对端沉默。
- **非定向 UDP 的内置心跳必须提供 `HealthProbe` 或 `HealthProbeFactory`**，因为内置探测发往远端，非定向通道没有远端。
- **心跳检测耗时**：自第一次探测开始约 `(MaxFailures − 1) × Interval + Timeout` 后判定；从监视器启动算起还要加一个 `Interval`，因为首次探测在启动后一个 `Interval` 才发出。不要把它当成"`MaxFailures × Interval` 内一定检出"。
- **通道忙不计失败**。探测排在请求锁上直到超时、一帧都没写出时，本次跳过，不影响连续失败计数。`NotConnected` 也不计失败。
- **`Sequential` 超时在 TCP 上默认断开重建**（`ResetOnRequestTimeout = true`）；串口与 UDP 不重建，而是进入迟到窗口。用户取消等待应答与超时同样处理。
- **`TcpServer.BroadcastAsync` 返回的是成功发送的会话数**，不是会话总数。

### 串口与 UDP

- **串口 `ReadBufferSize`、`WriteBufferSize` 必须为正偶数**（`SerialPort` 的要求）。它们只设置驱动缓冲，不改变通道读取的块大小。
- **串口打开遇到拒绝访问（`UnauthorizedAccessException`）会在 `OpenTimeout` 内每 20 ms 重试**，不是立即失败。驱动释放端口是异步的，刚关闭的端口可能短时间内仍被占用。
- **串口热拔插（USB 转串口在打开状态下拔出）尚未经人工验证**（计划第 19 节待办）。风险未复现也未排除，未添加防护代码。
- **`RemoteHost` 与 `RemotePort` 必须同时设置或同时不设置**。
- **定向模式的 `RequestAsync` 只能请求远端**；`RequestToAsync` 发往其他地址返回 `InvalidRequest`。非定向模式的 `RequestAsync` 返回 `InvalidRequest`，要用 `RequestToAsync`。
- **数据报的握手积压溢出是丢弃，不是断开**（与字节流不同）。设计第 11.1 节的通用描述以代码为准。
