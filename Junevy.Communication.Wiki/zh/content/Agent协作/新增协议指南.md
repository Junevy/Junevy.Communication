# 新增协议指南（地址型设备协议包）

面向在本仓库实现新的地址型协议包（S7、FINS 等）的智能体。开工前先读 [[Agent协作/开发约定与验收基线]]（AGENTS.md 硬性约定）与 [[架构设计/Plc 地址型设备协议套件]]。参照实现是 `Junevy.Communication.Melsec`；使用者与作者的完整说明见 [Skills/using-junevy-plc/SKILL.md](file://Skills/using-junevy-plc/SKILL.md)。

## 一、架构先行（AGENTS.md 第 2 节）

- 开工前设计架构，考虑扩展性、维护性与耦合性。协议包只依赖 Plc 与它所用的通道项目。
- 不修改 Core、Channels、Plc 的代码。需要改套件时，先说明套件缺口，再作为通用能力补进套件，并向用户提问。
- 发现更优的实现方式，或当前方式不符合设计规范，必须提问，并先检索是否有更好的方式。
- 不确定的功能先问，可扩展的功能先问是否扩展。

## 二、必须写与不需要写（设计 12.8）

| 必须写 | 套件已提供，不要重写 |
|---|---|
| 设备表与地址类型（`PlcAddressParser<TDevice, TAddress>`，设备实现 `IPlcDeviceDefinition`） | 连接、重连、心跳调度、超时 |
| 十个抽象钩子；需要时覆写 `ValidateRange`（表示范围与点数上限） | 请求串行化、重试、拆包、类型化读写 |
| 帧编解码（无通道依赖，放在 `Protocol/`） | 字节序转换、日志、注册表、工厂 |
| 传输配置（通道组件：分帧、关联、键提取器、心跳探测）与守卫 | TCP、UDP、串口的传输适配 |
| 协议的创建入口 `Create(IChannelConfig …)`（经 `PlcChannelBinding.CreateChannel`）、创建器、`AddX()` | 流式分帧的实现（只声明分帧） |
| 设备替身与端到端测试 | 模拟服务器（使用 Testing 的 `DeviceSimulator`） |

## 三、项目骨架

```
Junevy.Communication.<Name>/
  <Name>Address.cs             PlcAddress 派生类型（设备、编号、位号）
  <Name>DeviceTable.cs         声明式设备表与 PlcAddressParser（内部）
  <Name>ClientOptions.cs       PlcClientOptions 派生
  Protocol/                    帧编解码、请求体、应答解码
  <Name>Client.cs              PlcClientBase<TAddress> 派生：钩子与静态工厂
  <Name>ProtocolProfile.cs     通道组件（`Configure(components, options, delivery, medium)`）与守卫
  DependencyInjection/         配置类型（IPlcClientConfig）、创建器、AddX()
Junevy.Communication.<Name>.Tests/
  TestSupport/                 设备替身（PlcMemory + DeviceSimulator）、黄金向量
```

- csproj 与 Melsec 一致：`Import` `build/Junevy.Communication.Common.props`，`PackageReadmeFile` 为英文 README，测试项目 `Import` `build/Junevy.Communication.Tests.props`。
- 在 `Junevy.Communication.slnx` 中加入两个项目（库与测试）。

## 四、测试约定

- **黄金向量是唯一的正确性来源**：帧编码与解码按手册示例逐字节核对，手册给出两个方向时双向测试。
- **设备替身只翻译，不重写协议**：替身把请求翻译成 `PlcMemory` 操作，应答可复用协议层的字段编码；目标 200 行以内。
- **端到端矩阵**：每个传输 × 每种帧 × 每种编码；拆包（上限边界）；异常结束码；断开后重连再读取；静默设备加心跳进入 `Reconnecting`；有序列号的协议测迟到应答。
- **集合约定**：真实套接字或墙钟预算的测试类加 `[Collection(SocketTimingCollection.Name)]`，避免偶发失败。
- **等待用轮询**：`WaitUntilAsync` 类辅助，不用 `Thread.Sleep`。
- **`DuplexClientChannel` 的 `onOpened` 会被等待**：在回调中启动模拟器而不返回它的任务，否则连接挂起。
- **真实串口测试**（`SerialPairFact`）只在设置了 `JUNEVY_SERIAL_PAIR` 的机器上运行；执行者不运行，由审阅者运行。

## 七、P2 摩擦记录中的陷阱

完整记录见计划第 20.2 节，设计文档第 20.2 节是对应的实现修订表。

- 构建钩子返回 `void`，不能报告错误；可表示性检查放在 `ValidateRange`，编码器保留同一条件的守卫。
- 派生地址的设备属性需要 `new` 隐藏，调用方取具体设备要向下转换。
- `IFrameCodecFactory` 拿不到 `MaxFrameLength`；自定义分帧器需要自己保存上限，并与通道配置保持一致。
- `ChannelComponents` 会静默覆盖同名的传输配置设置；协议的配置方法要守卫。
- 通道族的统计对象构造函数与透传编码器是 internal；测试替身需要通过 `DuplexClientChannel` 或 Testing 的测试底座获得，而不是反射。
- 4C 格式 5 的分帧器要跳过成对的 `10H 10H`，之后才能找到未转义的 DLE ETX；当前实现每次到达都重新扫描缓存的字节，这是待 Channels 提供前进式读取器后改进的已知问题。
