## AGENTS.md 硬性约定（7 条）

1. **架构先行**：开工前设计好架构，考虑扩展性、维护性、耦合性；不为图快随手写逻辑。
2. **CHANGELOG 强制**：修改/新增任何逻辑后必须更新 `CHANGELOG.md`，**注明更新日期**与新增（修改）内容。格式参考 Keep a Changelog，版本遵循 SemVer。
3. **Skills 检索**：设计功能或 API 变更，必须检查仓库 `Skills/using-junevy-modbus/SKILL.md` 是否需要同步更新（它描述了 API 面、重命名陷阱与行为契约，过期会误导其他智能体）。
4. **README 同步**：破坏性更新或涉及 README 内容的更改，必须更新 `readme.md`（英文）。
5. **清理冗余**：功能开发/修改后必须清理无效逻辑代码。
6. **代码风格**：输出代码遵守当前类库风格（XML 注释中英混排现状、`PascalCase`、四空格缩进、region 式分组注释 `// ———— xxx ————`）。
7. **完整验收**：不能以 0 编译错误为目标，必须完整测试符合预期——见 [[测试/测试工程与验收方式]] 的验收清单。

## 补充工作约定（AGENTS.md 其他要求）

- 不明确的功能**必须提问**；可扩展的功能必须询问是否扩展；发现更优实现方式必须先检索再询问是否采用。

## 多目标框架技术约束（net472 生存指南）

**Modbus 库**多目标 `net472;net8.0`，源码**必须**双目标编译（通道族的约定见下文"通道族（P1，2026-10-10）开发约定"）：

| 禁用（net472 无） | 替代 |
|---|---|
| `Task.WaitAsync()` | 同步核心 + `#if NET8_0_OR_GREATER` 分支（见 `ModbusTcpClient.OpenConnectionAsync`） |
| `ArgumentNullException.ThrowIfNull` | 经典写法 `if (x == null) throw new ArgumentNullException(nameof(x));` |
| 其他 .NET 6+ API | 同上条件编译，并为 net472 提供降级实现 |

- 确需新 API 时用 `#if NET8_0_OR_GREATER` 并写清 net472 降级行为差异（现有注释模式：net8 取消即时生效 / net472 下一个 I/O 边界生效）。
- **Modbus 库项目不新增外部包依赖**（2026-10-05 计划的全局约束）。通道族按设计 Q3 允许微软一方包，见下文。
- 错误消息统一**英文**；改措辞必须同步更新依赖该文案的测试（消息文本钩子是子类覆写的原因之一）。
- 保持同步 + 异步双轨公开 API（`Request`/`RequestAsync`），不允许只做一份。**仅适用于 Modbus**；通道族只提供异步 API（设计 Q2）。

## 通道族（P1，2026-10-10）开发约定

以下约定来自计划第 0、1 节与设计文档。Modbus 的约定（上文）只适用于 Modbus；通道族以本节为准。

1. **只提供异步 API**（设计 Q2）。库内每个 `await` 都使用 `ConfigureAwait(false)`。
2. **依赖规则**（设计第 3.1 节；Q3、R1）：
   - 只向下依赖；同层协议包之间互不引用。
   - Core 不依赖 `System.IO.Pipelines` 与 `System.Threading.Channels`。
   - Channels 允许微软一方包（Pipelines、Threading.Channels）；第三方包只允许出现在 SDK 适配包中。
   - 传输包（Tcp、Udp、Serial）只依赖 Channels；Serial 另依赖 `System.IO.Ports` 8.0.0。
   - Channels 对 Tcp、Udp 开放 `internal`，Serial 不开放；第三方传输只能使用公开基类 `StreamClientChannel`（D12）。
3. **库项目设置**（D2、D3）：
   - 各库 csproj 显式 `<Import Project="..\build\Junevy.Communication.Common.props" />`。**不新增** `Directory.Build.props`，避免影响 Modbus。
   - `Common.props` 设定 `net472;net8.0`、`Nullable`、`LangVersion=latest`、`GenerateDocumentationFile`、`TreatWarningsAsErrors=true`、`Version=1.0.0-preview.1`；net472 额外编译 `build/Polyfills/*.cs`。
   - **不抑制 CS1591**：公开成员必须有 XML 注释。Modbus 的 CS1591 抑制是历史遗留，新代码不沿用。
   - 新库项目编译无警告（`TreatWarningsAsErrors`）。
4. **测试项目设置**（D4）：
   - 显式 `<Import Project="..\build\Junevy.Communication.Tests.props" />`；双目标 `net8.0;net472`。
   - `TestTfmsInParallel=false`：两个目标的测试进程串行运行，避免同时抢占端口与线程池。
   - 测试项目不 Import `Common.props`，因此不生成 XML 文档，也不把警告当作错误。
   - net472 测试宿主需要 `System.Memory` 的绑定重定向：`build/Junevy.Communication.Tests.app.config` 经 `AppConfig` 复制到各测试程序集的 `.dll.config`（原因见 [[测试/测试工程与验收方式]]）。
5. **配置校验**（D5）：非法配置抛 `ArgumentException` 系列；不改写调用方的配置对象。
6. **net472 禁用清单**（计划第 1 节第 4 条）：`Task.WaitAsync`、`ArgumentNullException.ThrowIfNull`、`Index` 与 `Range`（`^1`、`a..b`）、`init` 访问器与 `record`、`ArrayBufferWriter<T>`。确需新 API 时用 `#if NET8_0_OR_GREATER`，并在注释中写明 net472 的降级行为（`UdpDatagramTransport` 的 `SIO_UDP_CONNRESET` 即一例）。可空性特性（`NotNullWhen`、`MaybeNullWhen`、`DoesNotReturn`）由 `build/Polyfills/NullableAttributes.cs` 提供。
7. **代码风格**（计划第 1 节第 4 条）：文件作用域命名空间（与 `ModbusTcpClient.cs` 一致）；分组注释使用 `// ————— xxx —————`；错误消息与日志用英文，XML 注释用中文；TX/RX 十六进制日志只在 `logger.IsEnabled(LogLevel.Debug)` 时生成，避免提前求值。
8. **套接字测试**（计划第 1 节第 5 条）：放入各测试项目的 `SocketTiming` 集合（同集合串行，与纯内存测试并行）；除专门测超时的用例外，`ConnectTimeout` 统一设为 10000；耗时断言使用区间，下限取期望值的 80%，上限取期望值加 2000 ms；纯内存测试不加集合，否则会损失并行度。
9. **CHANGELOG**（计划第 1 节第 6 条）：通道族的条目写入 `CHANGELOG.md` 顶部的 `## [Unreleased] — 通讯通道族 P1` 节，格式 `- YYYY-MM-DD [包名] 内容`，日期为执行当天。
10. **不动 Modbus**（计划第 1 节第 8 条）：不修改 `Junevy.Communication.Modbus/` 与 `Tests/Junevy.Communication.Modbus.Tests/` 下的任何文件。

## 知识库回写约定
