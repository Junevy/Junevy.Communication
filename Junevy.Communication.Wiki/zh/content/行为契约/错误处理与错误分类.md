## 总契约

**结果式，公开操作不抛运行期异常。** Plc 套件（Modbus 与 MELSEC、S7、FINS 共用）的操作返回 `CommResult` / `CommResult<T>`：

- 失败必有 `ErrorMessage`（英文）与 `ErrorKind`（机器可读分类）。
- 成功 `ErrorKind == None`，`Data` 有效。
- 重试、重连与告警的决策**只看 `ErrorKind`**，禁止匹配 `ErrorMessage` 字符串。
- 协议级的错误码放在 `ProtocolErrorCode`（Modbus 的异常码、MC 结束码、S7 错误码等）。

构造期的配置错误仍然抛异常（例如 `RetryCount` 或 `RetryInterval` 为负时抛 `ArgumentOutOfRangeException`，见 [PlcClientBase.cs](file://Junevy.Communication.Plc/Client/PlcClientBase.cs)）。创建之后的所有操作都返回结果。

## CommErrorKind 语义表

数值 0–7 与 2.x 的 `ModbusErrorKind` 一一对应，所以 2.x 的 `ModbusException`（6）即 3.0 的 `RemoteError`（6）。

| Kind | 值 | 语义 | Modbus 中的来源 | 套件重试 |
|---|---|---|---|---|
| `None` | 0 | 成功 | — | — |
| `Unspecified` | 1 | 未分类；管线收口的未预期异常（记 Error 日志） | 管线的兜底分支 | 否 |
| `InvalidRequest` | 2 | 本地校验失败：地址、数量、参数，或写入 `IR` / `DI` | 地址解析、`ValidateRange`、写只读区 | 否，不发送 |
| `ConnectionClosed` | 3 | 连接断开或发送失败 | 通道层 | 是 |
| `Timeout` | 4 | 连接、读、写或应答超时；超时后到达的迟到应答被丢弃 | 通道层；MBAP 按事务号丢弃 | 是 |
| `ProtocolViolation` | 5 | 站号、功能码、字节数、回显、CRC、MBAP 协议号或长度不符 | `ModbusResponsePdu` 与 RTU / MBAP 解码 | 是 |
| `RemoteError` | 6 | 对端的协议级错误；Modbus 为异常响应（功能码 \| 0x80） | `ModbusResponsePdu` | **否，终态** |
| `Cancelled` | 7 | 调用方取消 | 通道层与管线 | 否 |
| `NotConnected` | 8 | 未连接，或已释放；未发送任何数据 | 管线的连接检查 | 否 |
| `AuthenticationFailed` | 9 | TLS 证书或登录失败 | 不由 Modbus 产生 | — |
| `ResourceExhausted` | 10 | 资源耗尽（会话数或队列已满） | 不由 Modbus 产生 | — |
| `NotSupported` | 11 | 协议或传输不支持该操作 | 位写入没有掩码写或读-改-写选项；0x16 不被设备支持时的异常码 01 也归为 `RemoteError` | 否 |

## 重试规则（P2-D7，套件）

- `RetryCount` 默认 0：快速失败，轮询循环本身就是重试。
- 重试针对单个请求；拆包时只重试失败的那一包。
- `Timeout`、`ConnectionClosed`、`ProtocolViolation` 在 `RetryCount > 0` 且 `RetryInterval` 内 `WaitForConnectedAsync` 成功时重试，否则返回真实的 `ErrorKind`。
- `RemoteError`、`InvalidRequest`、`NotSupported`、`Cancelled`、`NotConnected` 不重试。
- `RemoteError` 是设备的权威答复（例如 `IllegalDataAddress` 表示地址不存在），重试只会骚扰设备。调用方拿到它时**不要自己重试**。

Modbus 的解析与校验在 [ModbusResponsePdu.cs](file://Junevy.Communication.Modbus/Protocol/ModbusResponsePdu.cs) 中完成；异常应答先于其他校验被识别，因此不会被当成协议违规而重试。

## 异常逃逸边界

| 情形 | 结果 |
|---|---|
| 构造期的配置错误（`RetryCount`、`RetryInterval` 为负等） | 抛 `ArgumentOutOfRangeException` 等 |
| 公开操作的参数校验 | `InvalidRequest` 结果 |
| 管线中未预期的异常 | `Unspecified` 结果，消息为 `The operation failed unexpectedly during <操作名>.`，并记 Error 日志 |
| 客户端已释放后调用 | `NotConnected` 结果，消息为 `The PLC client has been disposed.` |
| 调用方取消 | `Cancelled` 结果，消息为 `The operation was cancelled by the caller.` |

其余通信故障（含协议违规、CRC 错、设备异常）都收敛为 `Fail` 结果。

## 面向调用方的处理建议

```csharp
CommResult<ushort[]> result = await client.ReadUInt16Async("HR100", 10);
if (result.IsSuccess) { /* use result.Data */ }
else switch (result.ErrorKind)
{
    case CommErrorKind.RemoteError: /* 设备答复异常：ProtocolErrorCode 为异常码，查地址与功能码，不要重试 */ break;
    case CommErrorKind.Timeout or CommErrorKind.ConnectionClosed:
        /* 网络或接线问题：RetryCount > 0 时套件已重试；仍失败时等后台重连恢复（或由宿主处理） */ break;
    case CommErrorKind.ProtocolViolation: /* 固件、干扰、波特率或帧不符：抓原始帧排查 */ break;
    case CommErrorKind.Cancelled: /* 调用方主动取消 */ break;
    case CommErrorKind.InvalidRequest: /* 编程错误：修参数 */ break;
    case CommErrorKind.NotSupported: /* 设备或库不支持该组合：换写法或换选项 */ break;
    case CommErrorKind.NotConnected: /* 未连接或已释放：检查生命周期 */ break;
    default: /* Unspecified：读 ErrorMessage；这通常意味着新加的错误路径忘了带 Kind，值得反馈 */ break;
}
```

现场排查时打开 Debug 日志可看到 `[TX]` / `[RX]` 的十六进制与毫秒差，失败帧也会随结果返回。

## 通道组件与传输配置的冲突（P25-D3）

| 场景 | 异常 | 来源 |
|---|---|---|
| `ChannelComponents.FrameCodec` 非 null，而传输配置的 `Framing` 不是该传输的默认值 | `ArgumentException`（通道构造时） | `ComponentPrecedence`（Channels） |
| `ChannelComponents.Correlation` 非 null，而传输配置的 `Correlation` 既不是默认值也不等于组件的值 | `ArgumentException`（通道构造时） | `ComponentPrecedence`（Channels） |

心跳、重连等补充型组件不做此检查。冲突先于参数错误报告。
