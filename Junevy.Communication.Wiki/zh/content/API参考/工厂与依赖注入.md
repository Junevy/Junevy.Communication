命名空间 `Junevy.Communication.Modbus.Factory`（DI 扩展在 `...Modbus.DependencyInjection`）。工厂 = 创建 + 注册表 + 别名 + 生命周期的门面。

## IModbusFactory 成员

| 成员 | 语义 |
|---|---|
| `Count` / `Keys` | 物理实例数 / 全部注册名（**含别名**） |
| `Get(key)` | 取实例或 null；空 key 返回 null（不抛） |
| `GetRequired<TResult>(key)` | 取并转型；找不到或类型不符抛 `InvalidOperationException` |
| `TryGet(key, out modbus)` | 尝试取 |
| `GetOrAdd(key, tcpConfig)` / `(key, rtuConfig)` | 原子取或建；已存在则**忽略传入的新 config** 返回旧实例 |
| `TryAdd(key, config, out modbus)` | key 已存在返回 false 且**新实例被立即 Dispose** |
| `TryRemove(key)` | 移除条目、连带清理别名、按引用情况决定是否 Dispose（见下） |
| `RegisterAlias(aliasKey, existingKey)` / `RemoveAlias(aliasKey)` | 别名增删（见下） |
| `Dispose()` / `DisposeAsync()` | 释放全部物理实例；之后任何操作抛 `ObjectDisposedException` |

## 校验与默认值回填（IModbusClientCreator.Normalize）

`GetOrAdd` / `TryAdd` 在解析出创建器后调用 `creator.Normalize(config)`，**回填逻辑由创建器持有**（2026-10-08 从 `ModbusFactory.ValidateAndFillDefaults` 迁入，行为不变）：

- `config == null` → `ArgumentNullException`；`key` 为空 → `ArgumentException`（两项留在工厂，不在创建器里）。
- TCP（`TcpClientCreator.Normalize`）：`Address`→`127.0.0.1`、`Port`→502、三个超时→2000、`RetryCount<0`→0、`RetryInterval<0`→100。
- RTU（`RtuClientCreator.Normalize`）：`PortName` 为空仍抛 `ArgumentException`；`BaudRate`→9600、`DataBits` 越界→8、两个超时→2000、`RetryCount<0`→0、`RetryInterval<0`→100、`FrameReadInterval<0`→30。
- **注意**：这与"库不改请求对象"是两回事——config 会被改写，调用方复用同一 config 实例注册多个连接时会看到被回填的值。见 [[Agent协作/常见陷阱与易错点]]。

## IModbusClientCreator — 工厂策略化（2026-10-08）

客户端创建不再由工厂按配置类型分叉，而是解析 `IModbusClientCreator`：

```csharp
public interface IModbusClientCreator
{
    Type ConfigType { get; }                        // 本创建器处理的配置类型（精确类型）
    void Normalize(IModbusConfig config);           // 校验并回填默认值
    IModbus Create(IModbusConfig config);           // 创建客户端
    string Describe(IModbusConfig config);          // 日志用目标描述，如 "192.168.1.100:502" / "COM3"
}
```

- **解析规则**：`GetOrAdd` / `TryAdd` 从 `config.GetType()` 开始沿 `BaseType` 链向上找第一个已注册的 `ConfigType`；找不到抛 `NotSupportedException`（消息含配置类型全名）。因此 `class MyTcpConfig : ModbusTcpClientConfig` 会命中 `TcpClientCreator`。
- **注册顺序决定优先级**：同一 `ConfigType` 出现多次时**枚举顺序靠后的覆盖靠前的**（与 Microsoft DI "最后注册者生效"一致）。DI 中内置创建器用 `AddSingleton` 注册，调用方必须**在 `AddModbusFactory()` 之后**注册自定义创建器才能覆盖；`ModbusFactoryBuilder.WithCreator` 追加在内置创建器之后。
- `GetOrAdd` / `TryAdd` 的固定执行顺序：`ThrowIfDisposed()` → `config == null` 抛 `ArgumentNullException` → `key` 为空抛 `ArgumentException` → `ResolveCreator` → `creator.Normalize(config)` → 日志（`creator.Describe(config)`）→ `manager.GetOrAdd(key, _ => creator.Create(config))` 或 `manager.Add`（`TryAdd` 重复键时 `Dispose` 刚创建的实例）。
- `ModbusFactory` 的构造函数只有两个：`ModbusFactory()` 与 `ModbusFactory(ILogger<ModbusFactory>, IEnumerable<IModbusClientCreator>, IModbusConnectionManager)`；`creators` 或 `manager` 为 `null` 抛 `ArgumentNullException`。

## ModbusConnectionManager — 注册表与别名

`ConcurrentDictionary<string, Entry>`，`Entry` 要么是直连实例（`IsDirect`）要么是别名目标名。

- **别名解析**：`Resolve` 沿别名链跳转，`visited` 集合做**环检测**（成环记 Error 日志返回 null）；目标缺失同样记 Error 返回 null。
- **`GetOrAdd` 并发竞态**（审查修复 B4）：不用 `ConcurrentDictionary.GetOrAdd` 的 valueFactory（竞态下可能执行多次、输家泄漏），改为 `TryGetValue/TryAdd` 自旋——**输家创建的实例立即 Dispose**，赢家路径唯一存活（测试 `GetOrAdd_ConcurrentRace_DisposesLosingInstances` 用 16 并发 + Moq 验证）。
- **`TryRemove` 级联清理**（2026-10-07 修正）：传入直接实例的键 → 递归删除**所有直接或间接指向它的别名**（`a → b → key` 链上的 `a`、`b` 一起删），然后 Dispose 实例（Dispose 抛异常时捕获记录，不阻断其余清理）；传入别名键 → 只删该别名，实例不动。若同一实例对象还被**另一个直接键** `ReferenceEquals` 引用，则不 Dispose（最后一个引用移除时才释放）。key 不存在返回 false。
  - 旧行为"有别名则只移除名字、实例保活"会造成**实例既不释放也不可达**的泄漏：别名解析已失败（`Get(alias)` 返回 null），`Dispose()` 遍历直连条目也找不到它 → 串口/套接字永久不释放。
- **`RegisterAlias` 校验**：目标键 `existingKey` 未注册、或者 `aliasKey == existingKey`、或者 `aliasKey` 已存在 → 记 Warning 返回 `false`（不再创建悬空别名）。
- **`RemoveAlias` 防误删**：目标是直连条目 → 记 Warning 返回 `false` 且**注册表保持不变**（不再"先删后插"）；条目不存在返回 false；是别名才删除并返回 true。
- **并发**：`TryRemove`/`RegisterAlias`/`RemoveAlias` 三个方法主体在同一私有 `registryLock` 内执行（别名链遍历 + 删除必须是原子的）；`Add`/`GetOrAdd`/`Get`/`TryGet` 保持无锁 `ConcurrentDictionary`。
- **`Dispose`/`DisposeAsync`**：只 Dispose 直连实例（去重，HashSet 兜底），异步版对 `IAsyncDisposable` 实例并行等待。

## AddModbusFactory — Microsoft DI 注册

`services.AddModbusFactory()`（全部 `TryAdd`，可重复调用不冲突）注册：

1. `ILoggerFactory` → `NullLoggerFactory.Instance`（容器没有时兜底）
2. `ILogger<ModbusFactory>`（让 DI 选中 6 参数 ModbusFactory 构造）
3. `IModbusPduValidator` → `ModbusPduValidator`（共享 PDU 校验器）
4. `IModbusFrameBuilder` → `ModbusFrameBuilder`
5. `TcpProtocolParser` / `RtuProtocolParser`
6. `IModbusConnectionManager` → `ModbusConnectionManager`
7. `IModbusClientCreator` ×2（`TcpClientCreator`、`RtuClientCreator`，用 `AddSingleton` 使后注册者胜）
8. `IModbusFactory` → `ModbusFactory`（注入 creators 与 manager）

**关键契约**：DI 中 `IModbusConnectionManager` 与 `IModbusFactory` **共享同一注册表**（审查修复 B5；测试 `AddModbusFactory_FactoryAndConnectionManagerShareRegistry` 固定）——直接从容器解析 `IModbusConnectionManager` 也能看到工厂创建的连接。全 singleton。

## ModbusFactoryBuilder — 无 DI 流式构建器（Prism/DryIoc 等）

```csharp
var factory = ModbusFactoryBuilder.Create()
    .WithLoggerFactory(ILoggerFactory)     // 默认 NullLoggerFactory；影响工厂与每个新建客户端
    .WithTcpParser(TcpProtocolParser)      // 默认 new TcpProtocolParser()
    .WithRtuParser(RtuProtocolParser)      // 默认 new RtuProtocolParser()
    .WithFrameBuilder(IModbusFrameBuilder) // 默认 new ModbusFrameBuilder()
    .WithConnectionManager(IModbusConnectionManager) // 默认新建自持；传独立实例可与宿主容器共享
    .Build();
```

- 私有构造，`Create()` 入口；所有 `With*` 对 null 抛 `ArgumentNullException`。
- `Build()` 每次返回**独立**工厂（测试 `Builder_Build_Twice_ReturnsIndependentFactories`）；未设置项与 `AddModbusFactory` DI 默认值一致；不要求 Microsoft DI 包。
- 工厂由调用方 `RegisterInstance` 进第三方容器，并负责在应用关闭时 Dispose（它拥有全部连接）。

## 生命周期速查

| 动作 | 后果 |
|---|---|
| `factory.Dispose()` | 管理器 Dispose → 全部直连实例 Dispose → 后续操作 `ObjectDisposedException` |
| `factory.TryRemove(key)` | 直接实例键 → 删除全部指向它的别名 + Dispose 实例（被别的直接键共享时只删条目不 Dispose）；别名键 → 只删别名 |
| `manager.GetOrAdd` 竞态失败 | 输家实例 Dispose（不泄漏） |
| `factory.TryAdd` 重复 key | 新建实例立即 Dispose，返回 false |
| 客户端 `Dispose()` 后再请求 | `ObjectDisposedException`（`ThrowIfDisposed`） |
