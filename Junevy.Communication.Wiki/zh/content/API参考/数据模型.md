命名空间统一为 `Junevy.Communication.Modbus.Core.Models`。全部为纯数据类（2026-10-05 重构后 `ModbusRequest` 已移除 UI 事件）。

## ModbusRequest — 请求（纯 DTO）

| 属性 | 类型 / 默认 | 说明 |
|---|---|---|
| `TransactionId` | ushort / 0 | **仅 TCP 有效**：由客户端每次请求自动分配（从 0 递增、回绕）并回写；手动赋值只对裸帧 API（`ModbusHelper.BuildRequestFrame`）生效 |
| `ProtocolType` | `ModbusProtocolType.TCP` | 传输层以客户端自身协议为准，**只被裸帧构建 API 读取**；库不修改它 |
| `SlaveId` | byte / 1 | 从站 ID |
| `FunctionCode` | `ModbusFunctionCode` / 0x10 | 功能码 |
| `StartAddress` | ushort / 0 | 起始地址（**协议级零基地址**）。旧名 `Start`（已破坏性更名） |
| `Quantity` | ushort / 3 | 数量：线圈按位、寄存器按个；0x07/0x0B/0x0C/0x11 忽略。旧名 `Length` |
| `Data` | `byte[]?` | 含义随功能码变化，见下表 |

### Data 布局（逐功能码，属性 XML 注释明文）

| 功能码 | Data 布局 | 校验（CheckRequest） |
|---|---|---|
| 0x05 WriteCoil / 0x06 WriteHoldingRegister | 恰好 2 字节（大端值；线圈 0xFF00=on / 0x0000=off） | 必须 2 字节 |
| 0x0F WriteMultipleCoils | 按位打包（低位在前），长度 = (Quantity+7)/8 | 数量 1–1968 且长度精确匹配 |
| 0x10 WriteMultipleHoldingRegisters | 按寄存器大端打包，长度 = Quantity×2 | 数量 1–123 且长度精确匹配 |
| 0x16 MaskWriteRegister | [AndMask(2), OrMask(2)] | 必须 4 字节 |
| 0x08 Diagnostics | [SubFunction(2), Data...]（原始 PDU 余部） | 3–252 字节 |
| 0x17 ReadWriteMultipleRegisters | [ReadStart(2), ReadQty(2), WriteStart(2), WriteQty(2), ByteCount(1), WriteData...] | ≥9 字节且读 1–125 / 写 1–121 / 字节数自洽 |
| 0x01/02/03/04 读类 | null（用 StartAddress+Quantity） | 数量范围内即可 |
| 0x07 / 0x0B / 0x0C / 0x11 | null | 无 |

## ModbusResult&lt;T&gt; — 结果

| 成员 | 说明 |
|---|---|
| `IsSuccess` | 成功与否（唯一应优先分支的属性） |
| `Data` | `T?`：成功为有效数据；失败时也可能携带原始帧（便于诊断） |
| `ErrorMessage` | 失败消息（**英文**；改动措辞须同步更新依赖文案的测试） |
| `ErrorKind` | `ModbusErrorKind`，失败时机器可读分类；成功为 `None` |
| `static Success(T)` | 构造成功结果 |
| `static Fail(msg, kind?, data?)` | 构造失败；不带 kind 时默认 `Unspecified` |

## ModbusErrorKind — 错误分类

| 值 | 枚举 | 语义 | 典型来源 | TCP 失败后重连？ |
|---|---|---|---|---|
| 0 | `None` | 未失败 | — | — |
| 1 | `Unspecified` | 未分类（历史兼容默认） | 裸 `Fail(msg)` | 否 |
| 2 | `InvalidRequest` | 本地校验失败（未上线） | CheckRequest | 否 |
| 3 | `ConnectionClosed` | 连接已断开/发送失败/未能重建 | EnsureConnected、SendFrame、远端关流 | 是 |
| 4 | `Timeout` | 连接/读/写超时 | Connect/Receive/Read 超时 | 是 |
| 5 | `ProtocolViolation` | 帧格式 / CRC / 长度违规 | 两解析器、PDU 长度校验 | 否 |
| 6 | `ModbusException` | 从站返回异常响应（FC\|0x80），消息含异常码 | 两解析器 | 否（**终态不重试**） |
| 7 | `Cancelled` | 取消令牌触发 | RequestAsync | 否 |

重连判断只看 `ErrorKind`（`ShouldReconnectAfterFailure`），**不匹配错误消息字符串**——这是 2026-10-05 引入 `ErrorKind` 的动机。

## ModbusFunctionCode — 功能码（15 个）

`ReadCoils=0x01`、`ReadDiscreteInputs=0x02`、`ReadHoldingRegisters=0x03`、`ReadInputRegisters=0x04`、`WriteCoil=0x05`、`WriteHoldingRegister=0x06`、`ReadExceptionStatus=0x07`、`Diagnostics=0x08`、`GetCommEventCounter=0x0B`、`GetCommEventLog=0x0C`、`WriteMultipleCoils=0x0F`、`WriteMultipleHoldingRegisters=0x10`、`ReportServerId=0x11`、`MaskWriteRegister=0x16`、`ReadWriteMultipleRegisters=0x17`。

注意枚举命名：单写是 `WriteCoil`/`WriteHoldingRegister`（不带 Single），多写是 `WriteMultiple*`；0x10 叫 `WriteMultipleHoldingRegisters` 而非 `WriteMultipleRegisters`。

## ModbusExceptionCode — 从站异常码（9 个 + Describe 扩展）

`IllegalFunction=0x01`、`IllegalDataAddress=0x02`、`IllegalDataValue=0x03`、`ServerDeviceFailure=0x04`、`Acknowledge=0x05`、`ServerDeviceBusy=0x06`、`MemoryParityError=0x08`、`GatewayPathUnavailable=0x0A`、`GatewayTargetDeviceFailedToRespond=0x0B`。

扩展方法 `Describe()`（`ModbusExceptionCodeExtensions`）返回英文短描述，未知码返回 `"Unknown exception code 0xXX"`。

## ModbusException — 线上异常的异常表达

`Exception` 子类，携带 `ModbusExceptionCode ErrorCode`。**注意**：结果式 API 路径上从站异常以 `ModbusResult.Fail(ModbusException)` 表达，`ModbusException` 对象主要用于解析器内部与测试断言场景；参数校验失败用标准 .NET 异常，不用它。

## 其他模型

- `ModbusProtocolType`：`TCP = 0x0000`、`RTU`。请求默认值是 TCP，但传输调用从不读它。
- `ModbusCommEventCounter`（0x0B 响应）：`Status`、`EventCount`（ushort×2）。
- `ModbusCommEventLog`（0x0C 响应）：`Status`、`EventCount`、`MessageCount`、`Events(byte[])`。
