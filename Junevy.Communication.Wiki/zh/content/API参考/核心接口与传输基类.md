## IModbus — 客户端公共契约

命名空间 `Junevy.Communication.Modbus.Core.Interfaces`。`ModbusTcpClient`、`ModbusRtuClient` 实现之；15 个功能码扩展方法也定义在 `IModbus` 上。实现 `IDisposable`。

| 成员 | 签名 | 说明 |
|---|---|---|
| `ProtocolType` | `ModbusProtocolType { get; }` | TCP 或 RTU（客户端恒定，扩展方法据此剥离帧头） |
| `IsConnected` | `bool { get; }` | TCP：socket 连接且 `Poll/Available` 探活通过；RTU：串口 `IsOpen`。Dispose 后恒为 false |
| `Connect()` | `bool` | 建立连接。不抛通信异常，失败返回 false（经请求锁） |
| `ConnectAsync()` | `Task<bool>` | 异步连接。net472 上不再是同步退化（2026-10-08 起真异步）。**参数 `CancellationToken`（2026-10-08 新增，默认值 `default`）**：用户取消抛 `OperationCanceledException`，连接失败或超时返回 `false` |
| `Disconnect()` | `void` | 断开。注意 `Reconnect=true` 时下一次请求会**静默重连**；`Dispose()` 之后调用为空操作 |
| `Request(tx)` | `ModbusResult<byte[]>` | 原始请求，返回完整 ADU（TCP 含 MBAP 头 / RTU 含 CRC 尾） |
| `RequestAsync(tx, ct)` | `Task<ModbusResult<byte[]>>` | 同上异步；`ct` 取消 → `Fail(Cancelled)` |

**不存在的 API**（旧版/猜测名，勿用）：`ConnectAsync(host, port)`、`CheckConnection()`、`SetPort()`。全表见 [[Agent协作/常见陷阱与易错点]]。

## IModbusConfig — 配置公共契约

TCP/RTU 配置类的公共面（只含重试相关；连接参数各自定义）：

| 成员 | 语义 |
|---|---|
| `ReadTimeout` / `WriteTimeout` | 读/写超时毫秒（注意拼写是 Timeout，旧版是 TimeOut）。TCP 异步路径同样生效；TCP 的 `ReadTimeout` 是**收满整个响应帧的总时限** |
| `RetryCount` | 首次失败后的重试次数（总尝试 = RetryCount + 1）。**需重建连接的失败仅在 `Reconnect=true` 时才重试** |
| `RetryInterval` | 重试/重连间隔毫秒 |
| `Reconnect` | 连接被销毁后（超时、对端关闭、发送失败）是否在重试前自动重建物理连接。为 `false` 时这些失败立即返回、不再重试，需调用方手动 `Connect()` |

完整配置项（含 TCP 的 `ConnectTimeout`、RTU 的串口参数与 `FrameReadInterval`）见 [[API参考/ModbusTcpClient]] 与 [[API参考/ModbusRtuClient]]。

## IModbusFrameBuilder — 请求帧构建

```csharp
int GetRequestFrameLength(ModbusRequest request, ModbusProtocolType protocolType);
bool TryWriteRequestFrame(ModbusRequest request, ModbusProtocolType protocolType,
                          Span<byte> destination, out int bytesWritten);
byte[] BuildRequestFrame(ModbusRequest request, ModbusProtocolType protocolType);
```

三条铁律（接口 XML 注释明文）：

1. **协议永远是显式参数**——实现绝不读取/修改 `request.ProtocolType`（测试 `FrameBuilder_ProtocolComesFromArgumentNotRequest` 固定）。
2. 写入 `Span<byte>` 零分配；缓冲不足返回 `false`（不抛）。
3. `GetRequestFrameLength` 对非法请求抛 `ArgumentException`；`BuildRequestFrame` 是兼容入口（内部走 TryWrite）。

默认实现 `ModbusFrameBuilder`（Core/Framing/），常量 `MaxRtuAduLength = 256`、`MaxTcpAduLength = 260`。帧布局见 [[协议细节/帧格式与CRC]]。

## IResponseParser — 响应解析

```csharp
ModbusResult<ReadOnlyMemory<byte>> ParseResponse(ReadOnlyMemory<byte> response, ModbusRequest request);
```

输入原始响应字节与**原始请求**，输出校验后的结果（成功 `Data` 为确认过的帧切片；失败携带 `ErrorKind`）。内置实现 `TcpProtocolParser` 与 `RtuProtocolParser`，规则见 [[协议细节/响应解析与PDU校验]]。可替换以适配非标准从站。

## ModbusTransportBase — 传输骨架与钩子表

`Core/Transports/ModbusTransportBase.cs`，抽象类，实现 `IModbus`。**公开 API 全部在此实现**（Connect/Disconnect/Request/RequestAsync/Dispose），子类只填协议差异。

### 抽象钩子（子类必须实现）

| 钩子 | TCP 实现 | RTU 实现 |
|---|---|---|
| `OpenConnection()` / `OpenConnectionAsync(ct)` | 地址/端口校验 → ResetSocket → BeginConnect（同步含 ConnectTimeout 并释放 AsyncWaitHandle；异步 net8 用 `Socket.ConnectAsync(host,port,ct)`，net472 用 FromAsync + WhenAny） | 关旧串口 → ConfigurePort → Open（异步 = `Task.Run`） |
| `CloseConnection()` | `Disconnect(false)` + 释放 stream/socket | 串口 Close |
| `InvalidateConnection()` | 释放 socket/stream（标记失效） | 串口 Close |
| `DisposeConnection()` | 同上（Dispose 路径） | 串口 Close + Dispose |
| `SendFrame` / `SendFrameAsync` | ArrayPool 租帧 → TryWrite → 循环 send → LogTx | 同 + `DiscardInBuffer/OutBuffer` 先行 |
| `ReceiveFrame` / `ReceiveFrameAsync` | 6 字节头 → PDU 长度校验(1–254) → payload → 解析 | Read-until-frame 循环（≥5 字节才解析，间隔 `FrameReadInterval`） |
| `ReconnectEnabled` / `RetryCount` / `RetryInterval` | 转发自 Config | 转发自 Config |
| `AssignsTransactionId` | **true**（锁内 `request.TransactionId = transactionId++`） | false |

### 虚钩子（子类按需覆写）

| 钩子 | 默认 | TCP 覆写 | RTU 覆写 |
|---|---|---|---|
| `GetNotConnectedMessage(isAsync)` | — | " [Request] Not connected." | " [Request] Port not open." |
| `GetSendFailedMessage(isAsync)` | — | " [Request] Send failed." | " [Request] Send frame failed." |
| `GetRequestFailedLogText(isAsync)` | — | " [Request] Request failed." | " [Request] Request execution failed." |
| `LogReconnectAttempt/Failed(ex, isAsync)` | — | TCP 措辞 | 串口措辞 |
| `LogRequestStarted(request, isAsync)` | 空 | 不记录 | Information 级记录请求 |
| `CreateInvalidRequestResult(request, isAsync)` | `Fail(Invalid request., InvalidRequest)` | + Warning 日志 | + 携带 `request.Data` |
| `RequiresNewConnection(result)` | **false** | `ErrorKind ∈ {Timeout, ConnectionClosed, ProtocolViolation}` 时 true（这类失败必须销毁连接才能重试；协议违规也销毁，避免残帧污染下一次请求） | 保持 false（RTU 不按 ErrorKind 重建连接） |

### 骨架内部状态

- `requestLock`（`SemaphoreSlim(1,1)`）：Connect/Disconnect/Request/RequestAsync 全串行化。**不 Dispose**（释放会使排队请求抛 `ObjectDisposedException` 逃逸），见 [[行为契约/重连重试与并发模型]]。
- `disposeState`（`int`）+ `disposeCts`（`CancellationTokenSource`）：Dispose 幂等与在途请求互斥，均不 Dispose；契约见 [[行为契约/重连重试与并发模型]]。
- `transactionId`（ushort 自增）：仅 TCP 使用。
- `stopwatch` + `lastTimestamp`：TX/RX hex 日志的时间差（`LogTx`/`LogRx` → `LogExtensions`）。
- `disposed`：Dispose 模板置位；`ThrowIfDisposed()` 守卫公开 API（`ObjectDisposedException`）。
- `IsCommunicationException(ex)`：静态白名单（7 类），决定哪些异常归为通信失败，见 [[行为契约/错误处理与错误分类]]。
- `ClassifyCommunicationException(ex)`：白名单异常 → `ErrorKind` 的映射（`TimeoutException` → `Timeout`，其余 → `ConnectionClosed`）。2026-10-07 加入——此前 `Request`/`RequestAsync` 捕获通信异常后构造的 `Fail` 不带 kind，一律落回 `Unspecified`。
- `EnsureConnectedAsync` 调用**真异步**的 `OpenConnectionAsync(ct)`（2026-10-07 起；此前 `Task.Run(OpenConnection)` 占线程池线程且不响应取消）。

### 新增传输类型怎么做

继承 `ModbusTransportBase`，实现抽象钩子 + 消息文本钩子，**不要**复制重试循环。参考 `ModbusRtuClient`（比 TCP 更简单的样板）。
