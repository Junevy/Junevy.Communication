## 通讯通道族 1.0.0-preview.1（2026-10-10，未发布）

本版本新增的是独立包，**没有破坏性变更**：Modbus 未改动，既有包不受影响，也没有需要迁移的 API。

| 包 | 内容 | 依赖 |
|---|---|---|
| `Junevy.Communication.Core` | `CommResult` / `CommResult<T>`、`CommErrorKind`、退避策略、`NamedRegistry<T>`、`TimeoutScope`、`HexFormatter` | Microsoft 抽象包、`System.Memory` |
| `Junevy.Communication.Channels` | 字节通道的接口与模型、六种分帧模式、`StreamClientChannel` 基类、`ChannelFactory`、`AddChannels`、文本扩展 | Core、`System.IO.Pipelines`、`System.Threading.Channels` |

发布状态（D1）：

- `1.0.0-preview.1` 只在仓库中构建产出 nupkg，**未执行 `nuget push`**。
- P2（Plc 套件 + MELSEC）用真实协议验证扩展性之后，才发布 `1.0.0`。验证中发现的通道层缺口可能需要调整公开 API，在此之前公开 API 可能变化（计划 D1）。
- 在 `1.0.0` 之前，安装包需要 `--prerelease`（见各包 README）。

## 2026-10-08 P2 引入的破坏性变更

| 变更 | 影响 |
|---|---|
| `IModbus.ConnectAsync(CancellationToken cancellationToken = default)` | 调用方源码兼容；**自行实现 `IModbus` 的类型**与表达式树调用（如 Moq 的 `Setup(m => m.ConnectAsync())`）需要更新签名 |
| `ConnectAsync` 用户取消时**抛出 `OperationCanceledException`**（此前无令牌、连接超时返回 false） | 依赖"取消也返回 false"的代码需改判 |
| TCP `ProtocolViolation` 现在销毁连接 | 需要在协议违规后继续复用同一连接的代码需改为 `Reconnect=true` |
| `Dispose()` 现在**等待在途请求**且在途/排队请求返回 `ConnectionClosed`（此前抛 `ObjectDisposedException`/`NullReferenceException` 或被永久挂起） | 依赖旧异常行为的代码需改判 `ErrorKind`；`Dispose` 可能比原来慢（等在途请求退出） |
| `Request`/`RequestAsync`/`Connect`/`Disconnect` 语义变化 | `Dispose` 之后调用抛 `ObjectDisposedException`（与 .NET 惯例一致）；`Disconnect` 后为 `Disconnect` 空操作 |

## 2026-10-07 P1 修复引入的破坏性变更

| 变更 | 影响 |
|---|---|
| `ShouldReconnectAfterFailure` → **`RequiresNewConnection`**（protected virtual 基类钩子） | 继承 `ModbusTransportBase` 的自定义传输必须改名；默认返回值不变（false） |
| `ModbusConnectionManager.TryRemove(主键)` **级联删别名 + 释放实例** | 依赖"删主键但保留实例、别名继续可用"的调用方**必须改为不删主键**（或把实例注册到另一个直接键下） |
| `RegisterAlias` 对悬空目标 / 同键返回 `false` | 依赖"别名可先注册、目标后建"的顺序会失败——必须先建实例再注册别名 |
| `RemoveAlias(直接键)` 不再"删除后放回" | 行为等价（都返回 false 且条目保留），但注册表不再被短暂移除，避免并发窗口 |
| 高层 API 的 `ErrorKind` 不再被重置为 `Unspecified` | 依赖 `Unspecified` 判断"未知错误"的调用方会看到具体 Kind——这是修复目标，不是意外 |
| 底层成功但数据过短 → `ProtocolViolation` 而非抛 `ArgumentException` | 捕获该异常的调用方需改判 `IsSuccess` |
| TCP `ReadTimeout` 在异步路径生效 | 此前异步挂起（不超时）的调用方现在会拿到 `Timeout`——**这是修复**，但会让"靠挂起实现轮询节奏"的代码暴露出来 |
| `Reconnect=false`（默认）时超时/连接关闭**不再重试** | 依赖默认 `RetryCount=3` 重试 4 次的调用方需显式 `Reconnect=true` |

## 1.0.x 破坏性变更全集（从旧版迁移必读）

### 重命名

| 旧 | 新 |
|---|---|
| `ModbusTCP` / `ModbusRTU` | `ModbusTcpClient` / `ModbusRtuClient` |
| 命名空间 `TCP` / `RTU` | `Tcp` / `Rtu` |
| `ModbusTCPConfig` / `ModbusRTUConfig` | `ModbusTcpClientConfig` / `ModbusRtuClientConfig` |
| `ReadTimeOut` / `WriteTimeOut` | `ReadTimeout` / `WriteTimeout` |
| `ModbusRequest.Start` / `.Length` | `.StartAddress` / `.Quantity` |
| `IntervalTime` | `FrameReadInterval` |
| `SetPort()` | 删除——`Port` 改普通可写属性 |
| `CheckConnection()` | 删除——用 `IsConnected` |
| `ToUshort(low, high)` | 删除——用 `BinaryPrimitives`/`ToBigEndian` |
| `ModbusException.ErrorCode`（旧类型） | 换为 `ModbusExceptionCode` 枚举 |
| `ShouldReconnectAfterFailure`（protected virtual 钩子） | `RequiresNewConnection`（2026-10-07 P1，默认 false 不变） |

### 目标框架与依赖

`net472;net6.0` → **`net472;net8.0`**；Microsoft.Extensions.* 与 System.IO.Ports 升至 8.0.0；生成 NuGet 文档文件；MIT 许可证表达式。

### 行为/契约变化（非重命名但可能破坏调用方假设）

- **库不再修改调用者的 `ModbusRequest`**（协议语义字段）；`IModbusFrameBuilder` 协议参数显式化；`ModbusRequest` 移除 UI 事件收敛为纯 DTO。
- TCP TID 库内自增 + **精确匹配**（旧约定 `+1` 且从不递增）。
- Modbus 异常响应在解析器层即失败（含异常码），**终态不重试**；旧版在裸 `Request` 层误报成功、RTU 侧被吞成超时。
- 结果式 API 不再逃逸异常（非法 MBAP 长度、RTU 零长解析帧 → 失败返回）；同步异步行为对齐。
- 重连判断基于 `ErrorKind` 不再匹配错误消息字符串。
- TCP 全链路真异步（net8 取消即时；net472 下一 I/O 边界）。

## 迁移检查单（旧版调用方升级）

1. 全局替换类型/命名空间名（上表）。
2. `Start/Length` → `StartAddress/Quantity`；`ReadTimeOut/WriteTimeOut` → `ReadTimeout/WriteTimeout`。
3. `SetPort`/`CheckConnection` 调用改为属性。
4. 处理返回值的代码确认走 `IsSuccess` + `ErrorKind`。
5. 手动管 TID 的代码删除（库托管）；依赖"异常响应返回成功"的代码按终态失败重写。
6. net6.0 宿主升级到 net8.0（或继续用包的 net472 目标）。
7. **（2026-10-07 P1）** 依赖重试的调用方确认 `Reconnect`——默认 `false` 时超时不再重试，需要自动恢复就显式设 `Reconnect = true`。
8. **（2026-10-07 P1）** 用别名共享 RS-485 总线的调用方复核：不要 `TryRemove(主键)` 还想留着别名；确认所有 `RegisterAlias` 的目标键都已注册。
