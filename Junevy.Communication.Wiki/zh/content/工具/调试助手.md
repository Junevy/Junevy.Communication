调试助手是 `Tools/Junevy.Communication.DebugAssistant` 下的 WPF 应用，**不是库**，不打包。用户操作见 `Tools/README.md`。决策编号 DA-D1 至 DA-D19 与逐 Task 的汇报在计划第 0 节与第 33 节。本笔记只记录实现后的结构与约定；与代码冲突时以代码为准。

## 结构

| 层 | 位置 | 内容 |
|---|---|---|
| 宿主与 DI | `Hosting/` | `ShellRegistration`（外壳与共享服务）；`SessionRegistration`（页签工厂表 `Pages`，并为每种种类生成键控服务） |
| 外壳 | `Shell/` | `ProtocolCatalog`（19 条描述，DA-D19 的登记表）、`ProtocolKind`、`ProtocolGroup`（PLC、工厂系统、自定义协议、模拟设备）、主窗口、树、页签 |
| 会话 | `Sessions/` | `SessionViewModel` 基类；`SessionServices`（Clock、Dispatcher、Files、Notifications、Transports、Confirm）；`SessionFactory`、`SessionNamer`、`ResultText` |
| 协议页签 | `Protocols/<协议>/` | 参数记录 `XxxSettings`、支持类 `XxxSupport`、行模型 `XxxRows`、视图模型 `XxxSessionViewModel` |
| 视图 | `Views/<协议>/` | 每页一个 UserControl；`Views/DataTemplates.xaml` 按视图模型类型匹配 |
| 日志 | `Logging/` | `SessionLog`（有界队列）、`SessionLogSink`（页签私有的 `ILoggerProvider`）、`FrameEntry`（报文条目） |
| 工作区 | `Workspace/` | `WorkspaceStore`（文件读写）、`SessionSettings`（`JsonPolymorphic` 联合类型） |
| 模拟器 | `Tools/Junevy.Communication.DebugAssistant.Simulators/` | 不引用协议包与 WPF（DA-D14）：存储区、引擎、故障注入、宿主 |

## 页签布局（2026-10-25）

- 协议页统一分区：顶部连接栏 `ConnectionBarView`；左侧参数列（`ColumnDefinition Width="340" MinWidth="260"`，`ScrollViewer` 用 `Panel.SettingsScroll`）| `GridSplitter`（`Splitter.Columns`）| 右侧工作区（`MinWidth="360"`）。工作区：主要内容（`*`）| `GridSplitter`（`Splitter.Rows`）| 底部活动区（固定初始高度 220–300，最小 120）。
- 底部活动区是原生 `TabControl`（由 Junevy.Controls 主题接管，没有关闭按钮），最后两页固定为"操作记录"（`OperationListView`）与"报文与日志"（`LogPanel`，`DataContext="{Binding LogPanel}"`），协议特有的输出列表放在它们前面。新页签照此写，不要再用 `jv:ExpanderPanel` 折叠日志或给操作记录固定高度——那是挤压问题的来源。
- 分隔条与左列滚动的样式在 `Views/Shared/FormResources.xaml`；主窗口的协议树分隔条也用 `Splitter.Columns`。
- DataGrid 的列不在视觉树中，列上的属性（如 `Visibility`）要绑定视图模型时经 `Views/Shared/BindingProxy`（Freezable 代理）绑定，直接 `{Binding}` 会静默失败（日志面板的列显隐曾因此失效）。
- 视图测试查找底部活动区或折叠分组里的元素用 `VisualTree.Reveal<T>`（选中所在页签、展开所在分组再排列）；`FindChild<T>` 只看已显示的视觉树。

依赖方向：视图依赖视图模型；视图模型依赖 `Sessions` 与各协议库的公开 API。`ViewModels`、`Services`、`Sessions` 不引用 WPF 或 Junevy.Controls（U2，架构测试守住）。

## 会话生命周期（DA-D9）

- 连接时把参数映射成库的选项并创建新的客户端。库的选项在 `Create` 时快照，所以改参数后重新连接即生效。
- 连接或启动期间参数区只读。
- 库的构造函数抛出 `ArgumentException` 时显示为参数校验错误，不崩溃。
- 关闭页签等于释放会话：断开、停止服务端或模拟器，限时 5 秒，失败写日志。退出程序时先保存工作区，再并发释放全部会话，总时限 10 秒。
- 释放只执行一次（`SessionViewModel.DisposeAsync` 有守卫，派生类改写 `DisposeCoreAsync`）：关闭过的页签在宿主退出时还会被 DI 容器再释放一次（2026-10-25 验收走查发现，第二次曾抛出 `ObjectDisposedException`）。
- 恢复工作区后页签一律未连接，不自动连接。

## 线程与结果（DA-D10，U5，U6）

- 库的事件在线程池上触发，统一经 `IUiDispatcher` 回到 UI 线程；测试里换成同步实现。
- 日志先进有界环形缓冲（每页签默认 5000 条），每 100 毫秒批量刷新到界面。
- UI 线程上的视图模型代码不加 `ConfigureAwait(false)`，因为继续执行要回到 UI 线程（计划第 3 节的例外）；其他代码照常加。
- 全程不同步等待异步操作（`.Result`、`.Wait()`、`GetAwaiter().GetResult()`）。
- **状态以库的当前状态为准**：库的 `StateChanged` 在线程池上触发，可能晚于后来的事件到达。通道、PLC、TCP 服务端、WebApi 服务端页签在处理器里读取库的当前状态；MQTT、OPC UA、SECS 页签要用事件里的原因文字，只应用 `Current` 与库当前状态一致的事件，过期的旧事件丢弃（最新状态的事件随后必然到达）。Task 21 修正通道页签，2026-10-25 补齐其余页签。新页签照此写。
- 三种结果（`CommResult`、`WebApiResult<T>`、`SecsResult`）统一映射为 `OperationRecord`，显示时间、操作、目标、耗时、成败、错误种类、协议错误码与消息。耗时用 `Since(started)` 按页签时钟计算（测试的假时钟下为 0），不要写 `TimeSpan.Zero`。
- DataGrid 的复选框列（`DataGridCheckBoxColumn`）默认双向绑定：绑定只读属性必须写 `Mode=OneWay`，否则出现第一行时抛异常（TCP 服务端页曾因此在客户端连上时崩溃，2026-10-25 修正）。

## 报文采集约定（DA-D5）

- 每个页签有自己的 `ILoggerFactory`，最低级别 `Debug`，挂一个页签私有的 `SessionLogSink`，不使用全局日志。
- 字节级报文来自库在 `Debug` 级别写出的模板：`TX {Length} bytes: {Hex}` 与 `RX {Length} bytes: {Hex}`；数据报写出 `… to {Destination}` 与 `… from {Remote}`。Sink 读取结构化状态里的 `Length`、`Hex`、`Destination` / `Remote`，生成报文条目，其余日志生成普通条目。
- **模板是契约**：测试锁定模板（Task 2）。库改了模板，测试失败，而不是悄悄丢失报文。
- **已知限制（F-1）**：库每帧最多输出 256 字节的十六进制，超出部分写成 `...(+N bytes)`。`FrameEntry` 标记截断：十六进制列显示"（已截断，共 N 字节）"，ASCII 列显示"（已截断）"。`Length` 仍是完整长度。
- MQTT、OPC UA、FTP、WebApi 没有字节级日志，页签显示操作记录与各包的事件。

## 工作区（DA-D11）

- 路径 `%LocalAppData%\Junevy.Communication\DebugAssistant\workspace.json`，`schemaVersion: 1`。
- 每个页签记录协议种类、标题、参数与选中项。参数记录按协议各一个，用 `[JsonPolymorphic]` 与 `[JsonDerivedType]` 区分，判别符见 `SessionSettings.cs`。
- 不保存密码：MQTT 与 FTP 的密码字段标 `[JsonIgnore]`。TLS 与 WebApi 的凭据只保存环境变量名，即以 `Variable` 结尾的属性。
- 文件损坏或版本不符时改名为 `.bak`，以空工作区启动并提示；不认识的种类跳过并提示；写入先写临时文件再替换。
- `AllKindsSettingsStoreTests` 遍历 `ProtocolCatalog.All` 的全部种类，保存、读回并应用后参数不变。

## 扩展一种页签（DA-D19）

需要四处登记，其他地方不得出现针对 `ProtocolKind` 的 `switch`：

1. `ProtocolCatalog`：加一条描述（种类、分组、标题、短名、图标）。
2. 参数记录加一行 `[JsonDerivedType]`。
3. 视图模型继承 `SessionViewModel`，在 `SessionRegistration.Pages` 加一行工厂。键控服务由目录自动生成；缺工厂时启动即失败，不退回占位页签。
4. 视图加一个按类型匹配的 `DataTemplate`。

`RegistrationRulesTests` 检查每个种类都有描述、参数类型、键控注册与 `DataTemplate`。

- 串口用例只在设置了 `JUNEVY_SERIAL_PAIR=COM20,COM21` 时运行；COM3 与 COM4 不得使用（DA-D16）。
- 截图：`JUNEVY_UI_SNAPSHOT_DIR` 渲染 19 个页签与 3 张整窗图（`UiSnapshotTests`）；`JUNEVY_ACCEPTANCE_DIR` 运行**验收走查**（`Acceptance/AcceptanceWalkthroughTests`，计划第 31 节第 3 条的清单：19 种页签改名关闭与工作区恢复、两种主题、MC / Modbus / S7 / FINS 与模拟器互连、故障注入、TCP 页互连、HTTP 与 REST 页互连），断言并渲染 PNG，验收截图放 `docs/superpowers/plans/assets/debug-assistant/`。走查在界面线程上运行（`UiThread.RunAsync`）：渲染过的视图会认领视图模型的集合，之后在别的线程改集合会抛跨线程异常。
- 会话智能体拿不到交互桌面（屏幕截图报"句柄无效"，模拟鼠标不到达窗口，computer-use 不认开发版程序），桌面手感（拖动分隔条、缩放）只能由用户确认。

## 模拟器（DA-D14）

- 存储区 `WordArea`、`BitArea`、`ByteArea`：加锁读写，越界抛出异常，写入后触发变化事件。`SimulatorMemory` 按名称登记，`TakeDirtyAreas` 汇总变化的区域，供界面节流刷新。
- 故障注入 `FaultPlan`：应答延迟、不应答、强制错误码、破坏校验、断开。"收到下一个请求后断开"只生效一次。
- 宿主挂到 TCP 服务端、非定向 UDP 或串口上；请求按到达顺序交给引擎，应答经同一队列按顺序发送；`RequestHandled` 事件供请求日志使用。
- 引擎：`ModbusSlaveEngine`、`McSlaveEngine`、`S7CpuEngine`、`FinsSlaveEngine`。黄金向量逐字节核对，见计划第 8 节。

## 收尾验收的决定（2026-10-25，用户授权代为决定）

- 生产重复窗口 90、测试重复窗口 39、C# 文件超过 300 行（15 个）：**接受为已知技术债**，列入路线图，不在本期重构。

- TCP 服务端停止时会话关闭不写操作记录（Task 6 偏差 7）：**接受**。
- U1 的两处 code-behind（OPC UA 浏览树双击转命令、模拟器内存表刷新计时器）：**接受为登记的例外**。
