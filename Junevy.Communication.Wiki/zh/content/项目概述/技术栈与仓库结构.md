## 解决方案布局

解决方案文件为 XML 格式 `.slnx`，含 38 个项目：库 16 个（Modbus 包、通道族 Core / Channels / Tcp / Udp / Serial、PLC 套件 Plc、Melsec、Siemens、Omron、Secs、WebApi、WebApi.Server、Mqtt、OpcUa、Ftp），测试 20 个（含测试套件 `Junevy.Communication.Testing`、共享服务器替身 `Junevy.Communication.Testing.Servers`、架构测试与调试助手测试），工具 2 个（调试助手与其模拟器，物理目录 `Tools/`，在解决方案中归入文件夹 `Tools`）。测试相关项目位于物理目录 `Tests/`，在解决方案中归入同名解决方案文件夹 `Tests`。

## Modbus 类库目标框架与依赖

多目标 `net472;net8.0`，`LangVersion=latest`，可空引用启用，`TreatWarningsAsErrors=true`，生成 XML 文档文件，**不抑制 `CS1591`**（P7 后与通道族一致；2.x 的抑制已移除）。

NuGet 元数据：`PackageId=Junevy.Communication.Modbus`，`Version=3.0.0-preview.1`（覆写 `Common.props` 的默认版本），`MIT` 许可证表达式，`GeneratePackageOnBuild=true`，`PackageReadmeFile` 为英文 README。

**项目依赖**：Modbus 的 csproj 不声明任何 NuGet 包，只引用本仓库的 `Junevy.Communication.Plc`、`Tcp`、`Udp`、`Serial` 四个项目。包依赖由它们传递，见下节。2.x 的包列表（DI 抽象、`System.IO.Ports` 等）已随 P7 移除。

**约束（Modbus）**：库项目不新增外部包依赖（P7 后的 csproj 只引用本仓库项目）。通道族允许微软一方包，见下节。

## 通讯通道族类库（Core / Channels / Tcp / Udp / Serial）

- 版本 `1.0.0-preview.1`，由 `build/Junevy.Communication.Common.props` 统一设置（D1，未发布）。
- 目标框架 `net472;net8.0`；`Nullable`、`LangVersion=latest`、`GenerateDocumentationFile`、`TreatWarningsAsErrors=true`，**不抑制 CS1591**（D3）。
- 每个库项目的 csproj 显式 `Import` `build/Junevy.Communication.Common.props`（D2：不使用 `Directory.Build.props`，避免影响 Modbus）。`Testing` 项目之外的库项目 `GeneratePackageOnBuild=true`，并通过 `PackageReadmeFile` 打包本包的英文 README.md。
- 包依赖（csproj 与打包后的 nuspec 一致）：

| 项目 | 依赖 | 说明 |
|---|---|---|
| `Junevy.Communication.Core` | `Microsoft.Extensions.DependencyInjection.Abstractions` 8.0.0、`Microsoft.Extensions.Logging.Abstractions` 8.0.0；net472 另加 `Microsoft.Bcl.AsyncInterfaces` 8.0.0、`System.Memory` 4.5.5 | 不依赖 Pipelines 与 Channels（R1）；net8.0 的共享框架已包含其余类型 |
| `Junevy.Communication.Channels` | 项目引用 Core；`System.IO.Pipelines` 8.0.0；`System.Threading.Channels` 8.0.0（仅 net472） | `InternalsVisibleTo` 开放给 `Tcp`、`Udp` |
| `Junevy.Communication.Tcp` | 项目引用 Channels | TLS 使用 BCL 的 `SslStream`，没有额外包 |
| `Junevy.Communication.Udp` | 项目引用 Channels | 没有额外包 |
| `Junevy.Communication.Serial` | 项目引用 Channels；`System.IO.Ports` 8.0.0 | 只使用公开基类，不开放 `internal` |
| `Junevy.Communication.Testing` | 项目引用 Channels | `IsPackable=false`，`GeneratePackageOnBuild=false`，不发布 |

依赖规则与理由见 [[架构设计/通讯库总体架构（协议族）]]。

## 测试项目依赖

Modbus 测试项目（P7-D18）：`Import` `build/Junevy.Communication.Tests.props`，目标 `net472;net8.0`，与通道族测试相同，测试框架与 SDK 版本由该 props 统一设置。项目引用 `Junevy.Communication.Modbus`、`Junevy.Communication.Melsec` 与 `Junevy.Communication.Testing`；另有 `Microsoft.Extensions.Configuration.Binder` 与 `Microsoft.Extensions.Configuration.Json` 8.0.0（测试中的配置绑定）。

通道族测试项目（`build/Junevy.Communication.Tests.props`）：Microsoft.NET.Test.Sdk 17.8.0、xunit 2.5.3、xunit.runner.visualstudio 2.5.3、coverlet.collector 6.0.0、Microsoft.Extensions.DependencyInjection 8.0.0；**不使用 Moq**。目标 `net8.0;net472`，`TestTfmsInParallel=false`。测试套件 `Junevy.Communication.Testing` 为项目引用，组件与用法见 [[测试/测试工程与验收方式]]。

```bash

dotnet test Tests/Junevy.Communication.Modbus.Tests        # Modbus 基线 307 通过、1 跳过（P7 Task 15，每个目标）
```

2026-10-10 全解决方案基线（分支 `feat/channels-p1`，commit `114d588`，Debug）：Modbus 405（net8.0）；通道族 Core 43、Channels 235、Tcp 116、Udp 32、Serial 57 + 2 跳过，每个测试项目在 net8.0 与 net472 上各一次。新库项目编译无警告，Modbus 项目仍有既有告警。
