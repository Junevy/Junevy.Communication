## 二、欠着的事（不属于某一期协议）

| 事项 | 现状 | 说明 |
|---|---|---|
| **正式发布** | 所有新包都是 `1.0.0-preview.1`（`build/Junevy.Communication.Common.props`），从未 `nuget push` | 设计 D1 原定"P2 用 MELSEC 验证扩展性之后发 `1.0.0`"，一直没做。发布前要定：哪些包一起发、版本号、公开 API 是否冻结 |
| **真机 / 真实服务器验证** | MELSEC、S7、FINS、SECS（HSMS）、MQTT、OPC UA 都只与模拟器或进程内的官方实现联调过；Modbus 已与第三方从站 pymodbus 互通（2026-10-26），真实设备、强噪声线路（②）与网关站号（⑤）待用户现场验证 | 各包 README 末尾都有"未验证清单"。现场接入时按清单逐条核对，发现的差异记回对应计划与本知识库 |
| **调试助手的技术债** | 生产重复窗口 90（WebApi 三个页签的视图模型占 61）、测试重复窗口 39、15 个 C# 文件超过 300 行（最大 `SimulatorSessionViewModel` 699 行） | 2026-10-25 收尾验收时接受为已知技术债（行为不变的重构，风险与收益不成比例）。做的时候先抽 WebApi 页签的共享基类 |
| **OPC UA 用户名登录** | **已完成**（2026-10-26，未提交）：`OpcUaClientOptions.UserName` / `Password`，只在 `None` 安全策略上；首次连接被拒返回 `AuthenticationFailed` 而不是 `Timeout`（F34）；调试助手 OPC UA 页加用户名、密码两栏（密码按用户选择保存到工作区）。见 [[协议细节/OPC UA 客户端]] 的"登录身份" | 仍然不行的：只在 Sign / SignAndEncrypt 上接受用户名的服务器（多数现场服务器）返回 `NotSupported`，要等下一行；明文密码令牌没有在真实服务器上验证 |
| **OPC UA 安全连接**（Sign / SignAndEncrypt、客户端证书与信任、证书登录） | 没有计划（P6.2 第 20 节） | 很多现场服务器关掉了 `None`，或只在加密连接上接受用户名，接入这类服务器之前必须做。开工前要定：客户端证书自动生成还是由调用方提供、服务器证书信任策略（自动接受 / 信任列表）、`PkiRoot` 的目录约定 |
| **串口热插拔** | 开发机没有 USB 转串口硬件，只有虚拟串口对 COM20 / COM21 | USB 拔出 / 重新插入后的重连行为没有验证；有硬件后补 |
