## 这是什么

本仓库是一个工业通讯类库族（`Junevy.Communication`），目前包含两部分：

- **Junevy.Communication.Modbus**：一个现代化、全异步的 Modbus **TCP / RTU / UDP 主站（master / client）** 通信类库，版本 `3.0.0-preview.1`（MIT 许可证）。它构建在 Plc 地址型协议套件之上，P7 从 2.x 迁移而来，属于破坏性更新，2.x 的写法已归档。下文的"核心定位"与"四个核心卖点"描述的都是这个包。
- **通讯通道族 P1**：`Junevy.Communication.Core / Channels / Tcp / Udp / Serial`，版本 `1.0.0-preview.1`，尚未发布。提供 TCP（含可选 TLS）、UDP 与串口的字节通道：连接生命周期（后台重连）、分帧、请求-应答关联、心跳与超时，以及 TCP 服务端。协议实现（三菱 MC、西门子 S7、SECS 等）按阶段在其上扩展，见 [[架构设计/通讯库总体架构（协议族）]]。

Modbus 包的核心定位：

- **只做主站**：连接并读写 Modbus 从站（PLC、仪表、网关）。**不做**从站（server）模拟、不做 Modbus ASCII，也不做诊断、文件记录、FIFO 与设备标识功能码。
- **地址式访问**：`ReadUInt16Async("HR100", 10)`、`WriteBoolAsync("C5", true)` 等类型化读写。站号写在地址前缀里（`s=2;HR100`），超出单包上限的请求自动拆包。
- **协议专有请求**：掩码写寄存器（0x16）与读写多个寄存器（0x17）。
- **多连接管理**：`PlcClientFactory` 命名注册表（`AddModbus()`）。RS-485 多站共享一条物理串口时，用站号前缀区分从站。

通道族的定位：只做**字节通道**，不做协议。字节流（TCP、串口）与数据报（UDP）各有一套统一的分帧、请求-应答关联、心跳、重连与超时实现；协议层通过 `ChannelComponents` 把自己的分帧、关联、握手与探活交给通道。

## 四个核心卖点（Modbus 包，来自 csproj 包描述，均已落实）

| 卖点 | 落实方式 |
|---|---|
| 全异步 | 所有操作都是 `*Async`，没有同步版本；net8.0 上 TCP 为真异步 I/O，`RequestTimeout` 在异步路径同样生效 |
| 后台重连 | 在通道配置中启用 `Reconnect`（默认关闭），由通道族在后台完成；`DisconnectAsync` 之后不会连回 |
| 线程安全 | 每个客户端的操作由操作锁串行化，读-改-写与分包都在锁内完成，杜绝并发收发交错 |
| 一键 DI | `services.AddModbus()` 注册工厂与创建器 |

## 结果式错误契约（最重要的使用约定）

读/写**不抛通信异常**，返回 `CommResult<T>`（`IsSuccess` / `Data` / `ErrorMessage` / `ErrorKind`）：

- 失败携带机器可读的 `CommErrorKind` 分类（超时、连接断开、协议违规、对端的异常响应……）。异常响应的异常码在 `ProtocolErrorCode`。调用方据此做重连、重试与告警决策，**不依赖错误消息字符串匹配**。
- 只有**创建时的配置错误**抛异常（例如 `RetryCount` 为负）；创建之后的操作全部返回结果。边界细节见 [[行为契约/错误处理与错误分类]]。

## 支持的功能码（10 个）

完整覆盖 `0x01–0x06`、`0x0F`、`0x10`、`0x16`、`0x17` 共 10 个功能码。诊断（07、08、0B、0C、11）、文件记录（14、15）、FIFO（18）与设备标识（2B）不做。协议细节与单包上限见 [[协议细节/Modbus 协议]]。

## 适用与不适用

| 适用 | 不适用 |
|---|---|
| .NET 应用作为 Modbus 主站轮询/控制从站 | 从站（server）模拟、协议穿透测试 |
| 工业上位机（WPF/WinForms/服务）多设备连接管理 | Modbus ASCII，以及诊断与文件记录功能码 |
| net472 遗留系统与 net8.0 新系统 | 站号 0 广播 |
| TCP、UDP 或串口，以及 RTU over TCP 网关 | 同步 API |
| 基于 TCP、UDP 或串口的自定义字节协议（扫码枪、视觉、ASCII 指令、带长度头的私有报文）：分帧、心跳、重连与超时由通道族提供 | 具体协议实现（三菱 MC、西门子 S7、SECS、WebAPI、OPC UA 等）：按阶段逐步提供，见 [[架构设计/通讯库总体架构（协议族）]] 的分期表 |
