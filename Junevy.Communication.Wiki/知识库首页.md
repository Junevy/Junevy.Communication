# Junevy.Communication 知识库

面向本仓库的知识库，包含两部分：

- **Modbus RTU/TCP 主站（客户端）通信类库**（`Junevy.Communication.Modbus`，net472 + net8.0 双目标）；
- **通讯通道族 P1**（`Junevy.Communication.Core / Channels / Tcp / Udp / Serial`，net472 + net8.0 双目标，版本 `1.0.0-preview.1`，未发布）。

共 24 篇正文笔记（不含本首页）。

> [!warning] 版本与时效
> 本知识库对应的代码基线：分支 **`feat/channels-p1`**，2026-10-10 回写时 `git rev-parse --short HEAD` 为 **`114d588`**。
> - **Modbus**：csproj `<Version>2.0.0</Version>`。Modbus 相关笔记按 **2026-10-08（P3 完成后）** 的代码逐篇核对；本次回写未改动 Modbus 代码。
> - **通讯通道族**：通道族相关笔记按 **2026-10-10** 的代码核对。
> - **2026-10-10 全解决方案单元测试基线**（`dotnet test Junevy.Communication.slnx -c Debug`，全部通过）：Modbus **405/405**（net8.0）；通道族 Core **43**、Channels **235**、Tcp **116**、Udp **32**、Serial **57** + 2 跳过（均为 net8.0 与 net472）。
>
> 与代码冲突时以代码为准。权威顺序：**代码 > 仓库 `AGENTS.md` > `CHANGELOG.md` > `docs/superpowers/` 计划与设计 > 本知识库正文**。
> 笔记内所有源码引用均为**文件级** `file://` 链接（相对仓库根，未写行号锚点），文件改名不会导致链接指向错误内容。

> [!tip] 给智能体的使用建议
> 1. **改动前先读** [[Agent协作/开发约定与验收基线]]（AGENTS.md 硬性约定与文档同步义务；通道族约定见其中的"通道族（P1，2026-10-10）开发约定"）与 [[Agent协作/常见陷阱与易错点]]（Modbus 的旧 API 名陷阱；第 8 节为通道族排坑）。
> 2. **写调用代码前查** [[API参考/功能码扩展方法]]（Modbus 方法签名与数量限制）、[[行为契约/错误处理与错误分类]]（`ModbusResult` / `ModbusErrorKind` 语义），以及 [[API参考/通道与传输（TCP UDP 串口 TLS）]]（通道族的类型、配置默认值与 DI 注册）。不要凭 NModbus、旧版记忆或设计文档草稿猜 API。
> 3. **理解行为先看** [[行为契约/重连重试与并发模型]]（Modbus：RetryCount 语义、重试与重连的分派规则、超时与取消、Dispose 契约、请求锁）与 [[行为契约/通道重连心跳与超时]]（通道族：超时总表、后台重连、心跳判定、迟到应答、Dispose 契约）。两者的重连语义不同，对比见后者。
> 4. **改完必须验收**：Modbus 为 `dotnet test Junevy.Communication.Modbus.Tests`（需 **405/405**）；通道族为 `dotnet test Junevy.Communication.slnx -c Debug`（双目标全绿，新库项目无编译警告）。验收基线见 [[测试/测试工程与验收方式]]。
> 5. **新增测试类**要遵守集合约定（真实套接字或毫秒级墙钟预算的类必须加 `[Collection(SocketTimingCollection.Name)]`），否则会引入偶发失败。通道族的各测试项目都有自己的 `SocketTiming` 集合定义。
> 6. **改完同一会话内回写本库**：公共 API、行为契约、协议细节或设计决策变化时更新对应笔记与本页版本号/基线 commit；**不自行提交**，用 `git -C <本库路径> status --short` 汇报改动，由用户决定提交。
> 7. 本库笔记直接位于 `zh/content/<主题>/` 下，**未设每主题 Hub 页**（与 Junevy.EasyCamera 知识库的差异）：主题规模小，本首页即全量索引。
