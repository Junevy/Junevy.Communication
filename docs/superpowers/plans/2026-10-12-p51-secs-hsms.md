## 0. 已固定的设计决策

| # | 决策 | 理由 |
|---|---|---|
| P51-D1 | 新增库 `Junevy.Communication.Secs`（依赖 Core + Channels + Tcp；不做 SECS-I，因此不引用 Serial）与测试项目 `Tests/Junevy.Communication.Secs.Tests`。csproj 与 Siemens 一致：Import `build/Junevy.Communication.Common.props`，版本 `1.0.0-preview.1`，`net472;net8.0`，英文 README 打包。命名空间：`Junevy.Communication.Secs`（消息模型、结果）、`Junevy.Communication.Secs.Hsms`（会话与设备端）、`Junevy.Communication.Secs.DependencyInjection`；内部的协议层放 `Protocol/`，命名空间 `Junevy.Communication.Secs.Protocol` | 设计 3.1、14.1 |
| P51-D2 | SECS 对外暴露自己的模型，**不实现** `IPlcClient`，也不把 HSMS 状态压成通道的 `ConnectionState`（设计 14.1）。公开类型只有第 9–14 节代码块列出的那些 | 设计 14.1；公开面最小 |
| P51-D3 | SECS-II 数据项（SEMI E5 第 9 节）支持：`L`、`B`、`BOOLEAN`、`A`、`I1` / `I2` / `I4` / `I8`、`U1` / `U2` / `U4` / `U8`、`F4` / `F8`。**不支持** `J`（JIS-8）与 `C2`（2 字节字符）：解码遇到它们按"非法数据"处理（设备端回 S9F7）。格式字节 = 格式码 << 2 \| 长度字节数，长度字节数 1–3，大端；列表的长度是子项个数，其余是字节数；数值一律大端 | 现场极少用 J 与 C2；YAGNI |
| P51-D4 | `A` 项按**单字节字符**处理：编码只接受 U+0000–U+00FF，超出抛 `ArgumentException`；解码时每个字节对应一个字符（Latin-1），无损往返。需要 GBK / UTF-8 文本的宿主自己转码后用 `B` 或在 `A` 里放字节（记入第 19 节，作为后续扩展） | E5 的 `A` 是单字节字符；不替宿主猜编码 |
| P51-D5 | 解码的防御上限：嵌套深度 ≤ 64；列表声明的子项数不能超过剩余字节数的一半（每个子项至少 2 字节头）；单条消息长度 ≤ `MaxMessageLength`（默认 16 MiB，可配置，同时作为分帧的 `MaxFrameLength`）。超出任一上限按非法数据处理，**不分配声明长度的内存** | 防止恶意或损坏的长度字段触发巨量分配 |
| P51-D6 | HSMS 报文 = 4 字节长度（大端，不含自身）+ 10 字节头 + 正文。头：会话号（2）、头字节 2、头字节 3、PType（1）、SType（1）、System Bytes（4）。数据消息的会话号是设备号，头字节 2 = W 位 << 7 \| Stream，头字节 3 = Function；控制消息的会话号为 0xFFFF。分帧：`LengthField`，偏移 0、宽 4、大端、修正值 0（设计 6.1 的 HSMS 行） | E37；与设计文档一致 |
| P51-D7 | 关联：`CorrelationMode.Keyed`，键 = System Bytes。键提取器**只给应答类消息取应答键**：数据消息中 Function 为偶数（含 0）的、`Select.rsp`、`Deselect.rsp`、`Linktest.rsp`、`Reject.req`（拒绝的是我们发出的消息，带同样的 System Bytes）。主消息（奇数 Function）与 `*.req` 控制消息不取应答键，因此作为主动消息派发——**否则对方主消息的 System Bytes 碰巧等于我方在途请求时会被错认成应答**。请求键：所有数据消息与 `Select.req`、`Linktest.req` | System Bytes 只在发送方内唯一 |
| P51-D8 | System Bytes 由进程级 `SequenceCounter` 的 `NextUInt16()` 产生（零扩展为 4 字节），挂在写头部的协议层类型上（P4.5 的做法）。设备端发出的主消息、控制请求与 S9 消息共用它 | 16 位在途唯一已足够；不改 Core |
| P51-D9 | 连接模式：`Passive`（默认，`TcpServer`，`MaxSessions = 1`，即 HSMS-SS 单会话）与 `Active`（`TcpClientChannel`，固定间隔重连）。计时器映射：<br>• T3（应答超时，默认 45000 ms）→ 每个带 W 位的主消息的 `RequestOptions.Timeout`；<br>• T5（连接间隔，默认 10000 ms）→ Active 的 `ReconnectOptions`（`FixedInterval`）；<br>• T6（控制事务超时，默认 5000 ms）→ Select 与 Linktest 请求的超时，以及 Active 的 `HandshakeTimeout`；<br>• T7（未选中超时，默认 10000 ms）→ Passive 的 `SessionHandshakeTimeout`；<br>• T8（字符间隔超时，默认 5000 ms）→ `PartialFrameTimeout`。<br>两种模式都设 `ResetOnRequestTimeout = false`：T3 超时是事务失败，不是链路失败。可选的 Linktest 心跳：`LinktestInterval` > 0 时启用心跳，间隔为它，超时为 T6，`MaxFailures = 1`，只在空闲时探测 | 设计 14.1 的映射表 |
| P51-D10 | 状态：`HsmsState { NotConnected, NotSelected, Selected }`，经 `StateChanged` 按发生顺序通知。TCP 连上即 `NotSelected`（由握手钩子开始时报告，服务端的 `SessionConnected` 在握手成功之后才发出），Select 成功即 `Selected`，断开即 `NotConnected` | E37 的连接状态模型 |
| P51-D11 | Select（HSMS-SS：只由 Active 一方发起）：<br>• **Passive**（握手钩子，在 T7 内循环）：收到 `Select.req` → 回 `Select.rsp`（状态 0）→ 握手成功；收到 `Linktest.req` → 回 `Linktest.rsp`，继续等；收到数据消息 → 回 `Reject.req`（原因 4"未选中"），继续等；收到 `Separate.req` → 握手失败（断开）；其余控制消息 → `Reject.req`（原因 1），继续等。<br>• **Active**：发 `Select.req`（超时 T6）；`Select.rsp` 状态为 0 → 成功；非 0、超时或收到 `Reject.req` → 握手失败，按 T5 重连 | E37.1；通道的握手积压正是为"被动端等待 Select.req"设计的（`IConnectionInitializer` 的 XML 注释） |
| P51-D12 | 已选中之后收到的消息（`FrameReceived` 派发）：<br>• `Linktest.req` → `Linktest.rsp`；<br>• `Select.req` → `Select.rsp`（状态 1"已激活"）；<br>• `Deselect.req` → `Reject.req`（原因 1，HSMS-SS 不用 Deselect）；<br>• `Separate.req` → 不应答，立即断开；<br>• 没有对应在途事务的 `Select.rsp` / `Deselect.rsp` / `Linktest.rsp` → `Reject.req`（原因 3"事务未打开"）；<br>• 迟到或无主的数据应答（偶数 Function）→ 记 Warning 并丢弃；<br>• PType ≠ 0 → `Reject.req`（原因 2，头字节 2 = PType）；未知 SType → `Reject.req`（原因 1，头字节 2 = SType）；<br>• 数据主消息 → 第 P51-D13 条 | E37 |
| P51-D13 | 设备端处理收到的数据主消息，依次判断：<br>① 会话号 ≠ `DeviceId` → 发 S9F1（正文为原消息的 10 字节头，`B` 项），不回应答；<br>② 正文解码失败或超出 P51-D5 的上限 → S9F7；<br>③ 该 Stream 没有任何处理器 → S9F3；有 Stream 但没有该 Function 的处理器 → S9F5；<br>④ 调用处理器：带 W 位时，处理器返回的应答必须是同一 Stream、Function + 1、不带 W 位，库按原 System Bytes 发回；处理器返回 null、返回了不匹配的应答或抛异常时，记 Error 并回 `S{n}F0`（中止事务）；不带 W 位时忽略处理器的返回值（非 null 时记 Warning）。<br>处理器按到达顺序**逐个**调用（同一连接上不并发），它可以在内部调用 `SendAsync` 并等待应答——应答由解析线程直接认领，不会死锁 | SEMI E5 S9 的设备端职责；顺序调用最可预测 |
| P51-D14 | 设备端发出主消息 `SendAsync`：<br>• 未选中 → `NotSelected`，不发送；<br>• 带 W 位 → 按 T3 等应答：正常应答 → 成功（`Reply` 为应答消息）；Function 为 0 → `Aborted`；`Reject.req` → `Rejected`（`RejectReason` = 原因码）；T3 超时 → 先发 S9F9（正文为我方主消息的 10 字节头），再返回 `ReplyTimeout`；应答解码失败 → 发 S9F7，返回 `InvalidReply`；<br>• 不带 W 位 → 只发送，成功时 `Reply` 为 null。<br>允许并发调用（Keyed 关联支持多个在途事务） | E5 / E37 |
| P51-D15 | `StopAsync` / 释放：已选中时先尽力发一条 `Separate.req`（不等应答），再关闭连接与监听；可重复调用；释放之后的 `SendAsync` 返回 `ConnectionLost`，`StartAsync` 抛 `ObjectDisposedException` | E37 的 Separate 用于通知对端 |
| P51-D16 | 日志：状态变化记 Information；每条收发记 Debug（方向、S/F、W 位、System Bytes，不含正文）；正文的 SML 文本只在 Trace 级输出（正文可能含配方等敏感数据）。模板一律常量（CA2254） | 与 WebApi 的日志脱敏原则一致 |
| P51-D17 | 依赖注入：`HsmsEquipmentFactory`（继承 Core 的 `NamedFactory<HsmsEquipment>`，`GetOrAdd(name, options)`）与 `SecsServiceCollectionExtensions.AddSecs()`；`HsmsEquipmentOptions` 全是简单属性，可从 appsettings 绑定 | 与 Plc 的工厂一致 |
| P51-D18 | 已知不确定项，写进 README 的"未经真机 / 真主机验证"清单：① Select.req 的会话号用 0xFFFF（HSMS-SS 常见做法）；② System Bytes 只用低 16 位；③ 处理器返回 null 时回 `SxF0` 而不是 S9F7；④ 不支持 J 与 C2 格式；⑤ T3 超时后先发 S9F9 再返回 | 诚实记录 |
| P51-D19 | 停止与释放（2026-10-13 补，细化 P51-D15）：<br>• **停止不是释放**：`StopAsync` 之后可以再 `StartAsync`，行为与第一次相同——Passive 重新监听；Active 重新连接，之后的意外断线照样按 T5 重连。`Stop → Start` 可以重复多轮。<br>• **释放**：先停止，之后永久不可用。`StartAsync` 抛 `ObjectDisposedException`；`SendAsync` 返回 `ConnectionLost`；`StopAsync`、`Dispose`、`DisposeAsync` 直接返回；`SetHandler` / `RemoveHandler` 只改处理器表、不抛异常。<br>• **停止或释放时仍在进行的操作**：<br>&nbsp;&nbsp;– 传给处理器的令牌被取消，等当前处理器返回后停止才完成，处理器此后返回的应答不发送。处理器必须响应令牌，README 写明。<br>&nbsp;&nbsp;– 在处理器内部调用 `StopAsync` 时不等它自己，否则死锁（同 `TcpServer.StopAsync` 在派发上下文里的做法）。<br>&nbsp;&nbsp;– 正在进行的 `StartAsync` 返回失败结果；等应答的 `SendAsync` 返回 `ConnectionLost`。两者都**不抛异常**。<br>• **不把通道的异常漏给调用方**：通道与 `TcpServer` 释放之后，`SendAsync` / `RequestAsync` 会抛 `ObjectDisposedException`。`HsmsEquipment` 要保证释放后不再调用通道，或者在边界把它翻译成 `ConnectionLost`。<br>• **不释放仍可能被使用的同步原语**（锁、令牌源）：可以只取消不释放，或者等所有使用者退出后再释放 | P6.1 验收的缺陷 R1（停止被当成永久停止）、R3（释放时释放了仍在使用的锁，释放后的操作抛异常），见 P6.1 计划第 18.1 节 |

**公开 API（固定）**

```csharp
namespace Junevy.Communication.Secs;

public enum SecsFormat
{
    List = 0x00, Binary = 0x20, Boolean = 0x24, Ascii = 0x40,
    I8 = 0x60, I1 = 0x64, I2 = 0x68, I4 = 0x70,
    F8 = 0x80, F4 = 0x90,
    U8 = 0xA0, U1 = 0xA4, U2 = 0xA8, U4 = 0xB0,
}

public sealed class SecsItem
{
    public SecsFormat Format { get; }
    public int Count { get; }                       // 列表的子项数，或数组的元素数、字符串的字符数、二进制的字节数
    public IReadOnlyList<SecsItem> Items { get; }   // 只对列表非空

    public static SecsItem L(params SecsItem[] items);
    public static SecsItem A(string value);
    public static SecsItem B(params byte[] values);
    public static SecsItem Boolean(params bool[] values);
    public static SecsItem I1(params sbyte[] values);
    public static SecsItem I2(params short[] values);
    public static SecsItem I4(params int[] values);
    public static SecsItem I8(params long[] values);
    public static SecsItem U1(params byte[] values);
    public static SecsItem U2(params ushort[] values);
    public static SecsItem U4(params uint[] values);
    public static SecsItem U8(params ulong[] values);
    public static SecsItem F4(params float[] values);
    public static SecsItem F8(params double[] values);

    public string GetString();                      // A
    public IReadOnlyList<byte> GetBinary();         // B
    public IReadOnlyList<bool> GetBooleans();
    public IReadOnlyList<sbyte> GetI1();   public IReadOnlyList<short> GetI2();
    public IReadOnlyList<int> GetI4();     public IReadOnlyList<long> GetI8();
    public IReadOnlyList<byte> GetU1();    public IReadOnlyList<ushort> GetU2();
    public IReadOnlyList<uint> GetU4();    public IReadOnlyList<ulong> GetU8();
    public IReadOnlyList<float> GetF4();   public IReadOnlyList<double> GetF8();

    public string ToSml();
    public override string ToString();              // 等于 ToSml()
}

public sealed class SecsMessage
{
    public byte Stream { get; }                     // 0–127
    public byte Function { get; }                   // 0–255
    public bool ReplyExpected { get; }              // W 位
    public SecsItem? Body { get; }

    public static SecsMessage Create(byte stream, byte function, bool replyExpected, SecsItem? body = null);
    public SecsMessage CreateReply(SecsItem? body = null);   // 同一 Stream、Function + 1、不带 W 位；对偶数 Function 调用抛 InvalidOperationException
    public string ToSml();
    public override string ToString();
}
```

1. 不可变：工厂方法复制传入的数组；访问器返回只读视图，格式不符时抛 `InvalidOperationException`（消息说明实际格式）。`L` 的子项不能为 null。`Create` 的 Stream > 127 抛 `ArgumentOutOfRangeException`；Function 为偶数且 `replyExpected` 为 true 抛 `ArgumentException`（应答不能带 W 位）。
2. SML 文本（只用于日志与调试，**不做解析**）：首行 `S1F1 W` 或 `S1F2`；正文每项一行、缩进两个空格；列表 `<L [2]` … `>`；`<A "EQ01">`（`"`、`\` 与 0x20–0x7E 以外的字节写成 `\xHH`）；`<B 0x80 0x01>`；`<BOOLEAN T F>`；数值 `<U4 1001>`，数组以空格分隔，浮点用不变区域性的往返格式；空项 `<U4>`；最后一行 `.`。具体格式以第 17.3 节的样例为准。
3. 测试：每种格式的构造、访问器、格式不符的异常、不可变（改原数组不影响项）、`CreateReply` 的规则，以及第 17.3 节的 SML 样例逐字比较。

## 17. 黄金向量

所有 HSMS 报文含 4 字节长度前缀。System Bytes 是我方计数器产生的值时，测试先把向量里的 System Bytes 换成实际值再比较（与 S7 的 PDU 引用号同法）。

### 17.1 HSMS

| 编号 | 含义 | 字节 |
|---|---|---|
