## 6. Task 2：`Arrival` 与 `LoopbackTcp`（F6、F10）

**API（固定）**

```csharp
namespace Junevy.Communication.Testing;

public static class Arrival
{
    public static Task<T> WithinAsync<T>(Task<T> pending, int milliseconds);
    public static Task WithinAsync(Task pending, int milliseconds);
}

public static class LoopbackTcp
{
    public const string Host = "127.0.0.1";

    public static TcpClientChannelConfig Client(int port);
    public static TcpClientChannelConfig Reconnecting(int port, int reconnectIntervalMs = 100);
    public static TcpClientChannelConfig WithHeartbeat(int port, int intervalMs = 100, int timeoutMs = 200, int maxFailures = 2, int reconnectIntervalMs = 200);
}
```

1. `Arrival.WithinAsync`：`Task.WhenAny(pending, Task.Delay(milliseconds))`；按时完成时返回（或 await）`pending` 的结果，让它自己的异常原样抛出；超时抛 `TimeoutException`，消息 `The awaited operation did not complete within {ms} ms.`。参数校验同 `Polling`。
2. `LoopbackTcp`：`Client` 只设 `Host` 与 `Port`；`Reconnecting` 另设 `Reconnect = new ReconnectOptions { Enabled = true, Interval = reconnectIntervalMs }`；`WithHeartbeat` 另设 `Heartbeat = new HeartbeatOptions { Enabled = true, Interval, Timeout, MaxFailures }` 与同样形状的 `Reconnect`。每次调用返回新对象（调用方可以继续修改）。默认值取自 S7 / FINS 故障用例里现有的字面量，**迁移时按现有值传参，不改变任何用例的时序**。
3. 测试：两个 `WithinAsync` 的按时完成、超时、`pending` 自身失败三种情况；`LoopbackTcp` 三个方法返回的配置逐字段核对，且两次调用返回不同实例。
4. 迁移：
   - `S7EndToEndFailureTests.FinishWithinAsync` 与 `FinsEndToEndFailureTests.ArrivesAsync` 删除，改用 `Arrival.WithinAsync`；Task 0 清单里其余同形助手，语义一致的一并迁移，不一致的保留并在汇报中说明。
   - S7、FINS 与 MELSEC 端到端用例中"`127.0.0.1` + 端口 + 重连 / 心跳选项"的字面量改用 `LoopbackTcp`；`S7ClientTests.Transport()`、`S7ClientHooksTests.Transport()`、`FinsClientTests.Transport()`、`FinsClientHooksTests.Transport()` 以及 DI 用例里的"标准端口 + 回环地址"改用 `LoopbackTcp.Client(102)` / `LoopbackTcp.Client(9600)`，保留"为什么必须给合法端口"的注释（F6）。
5. 证据：测试范围的 `S7EndToEndFailureTests ↔ FinsEndToEndFailureTests` 集群消失。CHANGELOG。提交：`test: share arrival and loopback TCP helpers`

## 7. Task 3：`PlcByteMemory`（F7，P46-D5、D6）

**API（固定）**

```csharp
namespace Junevy.Communication.Testing;

public enum PlcByteAccess
{
    Ok,
    NoSuchBlock,
    BeyondEnd,
}

public sealed class PlcByteMemory
{
    public byte[] Define(string area, int block, int length);
    public byte[] Block(string area, int block);
    public PlcByteAccess TryRead(string area, int block, int offset, int count, out byte[] data);
    public PlcByteAccess TryWrite(string area, int block, int offset, ReadOnlySpan<byte> data);
}
```

1. 语义：块由（区名，块号）标识，区名区分大小写；`Define` 新建全 0 的块并返回它，同一块重复定义抛 `InvalidOperationException`，长度 < 1 抛 `ArgumentOutOfRangeException`；`Block` 对未定义的块抛 `KeyNotFoundException`；`TryRead` / `TryWrite` 对未定义的块返回 `NoSuchBlock`，`offset + count` 超过块长返回 `BeyondEnd`（此时 `data` 为空数组、块不变），偏移或长度为负抛 `ArgumentOutOfRangeException`。内部一把锁（P46-D5）。
2. 测试：定义与预置、读写往返、`NoSuchBlock`、`BeyondEnd`（正好到块尾成功、超过一个字节失败）、写失败时块不变、重复定义与参数异常、并发写入不同偏移后结果完整。
3. 迁移：`S7DeviceSimulator` 删掉自带的 `Dictionary<(S7Area, int), byte[]>` 与越界判定，改用 `PlcByteMemory`（区名用 `S7Area` 的名称），`Block(area, db)` 改为转交 `PlcByteMemory.Block`——这是替身对用例的既有入口，保留它不算转发层，但它只能是一行；`FinsDeviceSimulator` 按 P46-D6 改用 `PlcByteMemory`，删除自己的位读-改-写与 `AreaCapacity` 越界判定。`FinsDeviceSimulatorTests` 与两个协议的全部端到端用例断言不改且全绿。
4. CHANGELOG。提交：`test: share a byte-granular PLC memory for simulators`
