## 0. 已固定的设计决策（P6.3）

| # | 决策 | 理由 |
|---|---|---|
| P63-D1 | 新增库 `Junevy.Communication.Ftp`（依赖 Core + FluentFTP 55.0.0）和测试项目 `Tests/Junevy.Communication.Ftp.Tests`。<br>命名空间：`Junevy.Communication.Ftp`、`.DependencyInjection`、`.Sdk`（内部，P6-C5）。<br>FluentFTP 里与本库同名的 `FtpClient` 在 `Sdk/` 中通过别名引用 | 设计 3.1；P6-C1、C5 |
| P63-D2 | 范围：<br>• FTP 与 FTPS（显式 `AUTH TLS`、隐式 TLS）；<br>• 数据连接**只用被动模式**（SDK 的自动被动：先 EPSV，不支持时退回 PASV）；<br>• 只用二进制传输。<br>不做 SFTP、主动模式、ASCII 传输 | 用户要求保持轻量；被动模式在 NAT 与防火墙后最可靠 |
| P63-D3 | 连接模型：<br>• 每个 `FtpClient` 持有一条控制连接，**按需连接**：每个操作开始时，未连接就先连接，因此可以不调用 `ConnectAsync`。调用它只是为了提前验证地址与凭据；<br>• 控制连接被服务器关闭（例如空闲超时）后，下一个操作会重新连接（借助 SDK 的断线检测，Task 6 用测试钉住）；<br>• 不发心跳（设计 14.3）；<br>• `DisconnectAsync` 发 QUIT 后断开；<br>• `IsConnected` 反映 SDK 当前的连接状态。<br>不提供状态事件：FTP 是请求式的，与 WebApi 相同 | 设计 14.3："每次操作一个连接"的场景不需要心跳；P6-C11 |
| P63-D4 | 串行：FTP 的控制连接一次只能执行一条命令，因此同一个客户端上的操作用一把异步锁**排队**执行（不是失败）。需要并行传输时，宿主创建多个客户端（工厂里用不同名称）。README 写明 | 协议限制；SDK 的异步客户端不支持同一连接上的并发操作 |
| P63-D5 | 路径：<br>• 远程路径按原样交给服务器，可以是绝对路径或相对于登录目录的路径；<br>• 为空时返回 `InvalidRequest`，为 null 时抛 `ArgumentNullException`；<br>• 上传的本地源文件不存在时返回 `InvalidRequest`，**不连接服务器**；<br>• 下载时本地父目录不存在就创建 | 本地参数错误应在联网前发现 |
| P63-D6 | 已存在时的处理：`FtpExistsMode { Overwrite, Skip }`。<br>• 上传看远程文件，下载看本地文件；<br>• `Skip` 且目标已存在时，结果成功，值为 `Skipped`，目标不变；<br>• 不提供续传与追加（第 19 节） | 与 SDK 的语义一致，并且只保留最常用的两种 |
| P63-D7 | **下载到文件是原子的**：先下载到同一目录下的临时文件（`<文件名>.<随机串>.part`），成功后再替换目标（`File.Move(..., overwrite: true)`）；失败时删除临时文件，原有的本地文件保持不变 | 配方、程序这类文件下载一半就被使用是事故 |
| P63-D8 | 目录与文件操作：<br>• `CreateDirectoryAsync` 逐级创建，已经存在算成功；<br>• `DeleteDirectoryAsync` **递归删除**（README 醒目写明），目录不存在时失败；<br>• `DeleteFileAsync` 文件不存在时失败；<br>• `RenameAsync` 源不存在时失败，目标已存在时的行为由服务器决定（README 写明）。<br>"不存在"的失败都是 `RemoteError`，有应答码时带应答码（通常是 550）。SDK 在这些情况下静默成功的，由本库先检查一次存在性，并用测试钉住（P6-C14） | 调用方需要知道操作有没有真正生效 |
| P63-D9 | 列目录：<br>• `ListAsync` 返回目录下的条目，不含 `.` 与 `..`；<br>• 服务器支持 MLSD 时用 MLSD，否则由 SDK 解析 LIST 的输出；<br>• 目录不存在时失败。如果 SDK 对不存在的目录返回空列表，本库只在**列表为空时**再检查一次目录是否存在，以区分"空目录"和"不存在"；<br>• `FtpEntry.Modified` 原样采用服务器报告的时间，不做时区换算（MLSD 是 UTC，LIST 通常是服务器本地时间，README 写明） | 避免把"不存在"误报为"空目录" |
| P63-D10 | 存在性与大小：<br>• `FileExistsAsync`、`DirectoryExistsAsync` 返回 `CommResult<bool>`；<br>• `GetFileSizeAsync` 在文件不存在或服务器不提供大小时失败（`RemoteError`），不用 -1 这类哨兵值 | 结果对象表达失败 |
| P63-D11 | 进度：`IProgress<FtpTransferProgress>`，包括已传输字节数，以及总长已知时的百分比（0–100，总长未知时为 null）。在 SDK 的回调线程上报告，README 写明 | 大文件传输的常见需求 |
| P63-D12 | 编码：选项 `EncodingName`：<br>• 为 null 时，服务器支持 UTF-8 就用 UTF-8，否则用 SDK 的默认编码；<br>• 指定时（例如 `GBK`）按名称取编码，并注册 `CodePagesEncodingProvider`（.NET 8 需要注册后才能用 GBK）；<br>• 名称无效时，`Create` 抛 `ArgumentException` | 国内老旧设备与 Windows FTP 服务器常用 GBK 文件名 |
| P63-D13 | FTPS：`FtpEncryption { None, Explicit, Implicit }` 与 `AllowUntrustedCertificates`：<br>• 后者为 true 时接受任何证书与主机名不符，`Create` 时记 Warning；<br>• 数据连接同样加密（PROT P）；<br>• TLS 失败归为 `AuthenticationFailed`（Tcp 的先例）；<br>• 隐式 FTPS 通常用 990 端口，由宿主设置，README 写明 | 用户选择纳入 FTPS |
| P63-D14 | 超时：<br>• `ConnectTimeout`：建立控制连接；<br>• `ReadTimeout`：等待控制连接上的应答；<br>• `DataConnectionTimeout`：建立数据连接和读取数据。<br>不使用 SDK 的自动重试与传输校验 | 与已有包的命名一致；重试由宿主决定 |
| P63-D15 | 日志：SDK 的日志经它的日志接口桥接（P6-C10），级别 Verbose → Trace、Info → Debug、Warn → Warning、Error → Error。SDK 的主机、用户名、密码脱敏开关保持默认（全部脱敏），**不允许打开**；本库自己的日志记录操作、远程路径、字节数、耗时 | P6-C10 |
| P63-D16 | 依赖注入：`FtpClientFactory`（`NamedFactory<FtpClient>`）与 `FtpServiceCollectionExtensions.AddFtpClients()` | P6-C9 |
| P63-D17 | 已知不确定项，写进 README 的"Verification status"：<br>① 只与测试中的模拟服务器联调过，没有对 vsftpd、FileZilla Server、IIS FTP、PLC 或设备内置的 FTP 服务器验证；<br>② LIST 输出的解析依赖 SDK；<br>③ 修改时间不做时区换算；<br>④ 重命名到已存在的目标时，行为由服务器决定 | 诚实记录 |

### 6. Task 2：模型、选项与错误映射（P63-D6、D9–D14，第 16 节）

**公开 API（固定）**

```csharp
namespace Junevy.Communication.Ftp;

public enum FtpEncryption { None, Explicit, Implicit }

public enum FtpEntryType { File, Directory, Link }

public enum FtpExistsMode { Overwrite, Skip }

public enum FtpTransferStatus { Transferred, Skipped }

public sealed class FtpEntry
{
    public string Name { get; }
    public string FullName { get; }          // 服务器上的完整路径
    public FtpEntryType Type { get; }
    public long? Size { get; }               // 目录或未知时为 null
    public DateTime? Modified { get; }       // 服务器报告的时间，不做时区换算；未知时为 null
}

public sealed class FtpTransferProgress
{
    public long TransferredBytes { get; }
    public double? Percent { get; }          // 0–100；总长未知时为 null
}

public sealed class FtpClientOptions
{
    public string? Host { get; set; }                       // 必填
    public int Port { get; set; } = 21;                     // 隐式 FTPS 通常为 990，由宿主设置
    public string? UserName { get; set; }                   // null 表示匿名登录
    public string? Password { get; set; }
    public FtpEncryption Encryption { get; set; } = FtpEncryption.None;
    public bool AllowUntrustedCertificates { get; set; }
    public string? EncodingName { get; set; }               // 例如 "GBK"；null 见 P63-D12
    public int ConnectTimeout { get; set; } = 10000;        // 毫秒
    public int ReadTimeout { get; set; } = 15000;           // 毫秒
    public int DataConnectionTimeout { get; set; } = 15000; // 毫秒
}
```

1. `FtpEntry`、`FtpTransferProgress` 的构造函数为 `internal`，只由 `Sdk/` 的映射创建。
2. 选项校验（`Create` 时调用），非法时抛 `ArgumentException` 族，消息写明属性名与范围：
   - `Host` 不能为空；`Port` 为 1–65535；
   - 三个超时 > 0；
   - 枚举取值已定义；
   - `EncodingName` 能解析为编码；
   - 有 `Password` 时必须有 `UserName`。
3. 内部类型：错误映射（第 16 节）、条目与进度的映射，全部放在 `Sdk/`。
4. 测试（不需要服务器）：

   - `EncodingName = "GBK"` 能解析（证明编码提供程序已注册）；
   - 第 16 节的每一行（构造 SDK 的异常或状态，断言分类与 `ProtocolErrorCode`）；

### 7. Task 3：模拟服务器、连接与 FTPS（P63-D3、D13、D14、D15）

**公开 API（固定）**

```csharp
namespace Junevy.Communication.Ftp;

public sealed class FtpClient : IDisposable, IAsyncDisposable
{
    public static FtpClient Create(FtpClientOptions options, ILoggerFactory? loggerFactory = null);

    public bool IsConnected { get; }
    public Task<CommResult> ConnectAsync(CancellationToken cancellationToken = default);
    public Task DisconnectAsync(CancellationToken cancellationToken = default);

    public Task<CommResult<IReadOnlyList<FtpEntry>>> ListAsync(string remoteDirectory, CancellationToken cancellationToken = default);
    public Task<CommResult<bool>> FileExistsAsync(string remotePath, CancellationToken cancellationToken = default);
    public Task<CommResult<bool>> DirectoryExistsAsync(string remotePath, CancellationToken cancellationToken = default);
    public Task<CommResult<long>> GetFileSizeAsync(string remotePath, CancellationToken cancellationToken = default);

    public Task<CommResult<FtpTransferStatus>> UploadFileAsync(string localPath, string remotePath,
        FtpExistsMode existsMode = FtpExistsMode.Overwrite, IProgress<FtpTransferProgress>? progress = null,
        CancellationToken cancellationToken = default);
    public Task<CommResult<FtpTransferStatus>> UploadAsync(Stream source, string remotePath,
        FtpExistsMode existsMode = FtpExistsMode.Overwrite, IProgress<FtpTransferProgress>? progress = null,
        CancellationToken cancellationToken = default);
    public Task<CommResult<FtpTransferStatus>> DownloadFileAsync(string remotePath, string localPath,
        FtpExistsMode existsMode = FtpExistsMode.Overwrite, IProgress<FtpTransferProgress>? progress = null,
        CancellationToken cancellationToken = default);
    public Task<CommResult> DownloadAsync(string remotePath, Stream destination,
        IProgress<FtpTransferProgress>? progress = null, CancellationToken cancellationToken = default);

    public Task<CommResult> DeleteFileAsync(string remotePath, CancellationToken cancellationToken = default);
    public Task<CommResult> CreateDirectoryAsync(string remotePath, CancellationToken cancellationToken = default);
    public Task<CommResult> DeleteDirectoryAsync(string remotePath, CancellationToken cancellationToken = default);
    public Task<CommResult> RenameAsync(string remotePath, string newRemotePath, CancellationToken cancellationToken = default);

    public void Dispose();
    public ValueTask DisposeAsync();
}
```

流的约定：库不释放调用方传入的流。上传从流的当前位置读到末尾，下载从流的当前位置开始写。

本 Task 实现 `Create`、`IsConnected`、连接、断开、释放与按需连接的骨架。其余操作先返回 `NotSupported` 的占位，最后一个占位在 Task 5 提交前删掉。

1. 模拟服务器 `TestSupport/`（按职责拆成多个文件），提供下列能力：
   - **基本**：内存文件系统（目录、文件内容、修改时间）；控制连接监听回环地址的随机端口；被动模式的数据连接（EPSV 与 PASV）；
   - **登录**：用户名与密码校验，或匿名；
   - **可切换的特性**：是否在 FEAT 中声明 UTF8、MLST、SIZE、MDTM；文件名编码用 UTF-8 还是 GBK；
   - **TLS**：显式（`AUTH TLS`、`PBSZ`、`PROT P`）与隐式，证书用 `TestCertificates`；
   - **故障注入**：
     - 指定命令或路径返回指定应答码（例如 STOR 返回 552，对 `/locked` 的 RETR 返回 550）；
     - 第 N 条命令之后关闭控制连接；
     - 数据传输到一半时中断（426）；
     - 拒绝数据连接（425）；
     - 某条应答延迟超过 `ReadTimeout`；
   - **记录**：收到的命令序列（带连接编号与时间），供串行检查（Q42）使用。
2. 测试（真实套接字）：
   - 用户名密码登录与匿名登录都成功；密码错误时为 `AuthenticationFailed`，`ProtocolErrorCode` 为 530；
   - 端口没有监听：`ConnectionClosed`；用 `SilentTcpServer` 接受连接但不回应：`Timeout`；调用方取消：`Cancelled`；
   - 显式与隐式 FTPS（`AllowUntrustedCertificates = true`）都成功，模拟服务器看到 `PROT P`，并且数据连接是加密的；`AllowUntrustedCertificates = false` 时为 `AuthenticationFailed`；
   - `DisconnectAsync` 发出 QUIT，`IsConnected` 变为 false；可以重复调用；
   - 释放的规则（P6-C8）；
   - 日志：任何级别都不出现密码（Q40，含 SDK 桥接的日志）。
3. 提交：`feat(ftp): add the FTP connection and the test server`

### 8. Task 4：列目录、存在性与目录操作（P63-D5、D8、D9、D10）

1. 测试：
   - **按需连接**（P63-D3）：没有调用 `ConnectAsync` 时，第一次 `ListAsync` 自动连接并成功；
   - **列目录**：MLSD 与 LIST 两种模式下，名称、类型、大小（目录为 null）、修改时间都正确，不含 `.` 与 `..`；空目录成功并返回空列表；目录不存在时失败（`RemoteError`）；
