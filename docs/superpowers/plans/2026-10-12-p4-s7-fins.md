## 0. 已固定的设计决策

| # | 决策 | 理由 |
|---|---|---|
| P4-D1 | 范围（用户 2026-10-12 决定）：**S7comm 经典协议，只做 S7-1200 / S7-1500**，经 ISO-on-TCP（RFC 1006，端口 102）；**FINS 只做 TCP**（端口 9600）；套件增加字节寻址与字符串扩展。不做：S7comm-plus（符号访问、优化块）、S7-300/400/200 SMART/LOGO!（只是连接参数不同，但本期不测试、不宣称支持）、S7 定时器与计数器（T/C 区）、FINS/UDP、Host Link 串口、NJ/NX 的变量名（标签）访问 | 用户决定；范围可控 |
| P4-D2 | 新增两个库：`Junevy.Communication.Siemens`（依赖 Plc + Tcp）与 `Junevy.Communication.Omron`（依赖 Plc + Tcp），以及两个测试项目 `Tests/Junevy.Communication.Siemens.Tests`、`Tests/Junevy.Communication.Omron.Tests`。csproj 与 Melsec 一致：Import `build/Junevy.Communication.Common.props`，版本 1.0.0-preview.1，net472;net8.0，英文 README 打包 | 设计 3.1、第 12 节；包名沿用设计文档 |
| P4-D3 | **允许的套件改动只有这些**（全部在里程碑 1 完成）：S1 `PlcAddressUnit.Byte`；S2 解析器的位号上限按单位决定；S3 `IPlcClient` 新增 `ParseAddress`、`ReadBytesAsync`、`WriteBytesAsync`；S4 `PlcAccess.Bytes` 与三个字节钩子；S5 读位钩子由 abstract 改为 virtual；S6 新钩子 `CanWriteBitsNatively`；S7 字节软元件上的位访问；S8 字符串与单字节扩展。Core 与 Channels **不改**。 | 设计 P2-D4 已预告 `Byte` 留到 P4；字符串扩展为用户决定；其余是 S7 与 FINS 的真实缺口，作为通用能力补进套件（新增协议指南第一节） |
| P4-D4 | `IPlcClient` 新增三个成员。这是对外部实现者的**破坏性变更**（预览版允许，写入 CHANGELOG 的"破坏性变更"）。语义：<br>• `ParseAddress(string)`：同步、无 I/O、线程安全；返回 `CommResult<PlcAddress>`，非法时为 `InvalidRequest`；释放后仍可调用。<br>• `ReadBytesAsync(address, count)`：字节软元件按字节精确读取；字与位软元件读取覆盖这些字节的整字（`ceil(count / 2)` 个），返回规范化布局的前 `count` 个字节。<br>• `WriteBytesAsync(address, data)`：字节软元件精确写入；字与位软元件要求长度为偶数，否则返回 `InvalidRequest`（消息说明字软元件只能整字写入）。<br>三者都不接受带位号的地址（`InvalidRequest`，与 `ReadAsync` 相同） | 宿主能在加载配置时校验地址；字符串扩展需要知道单位；S7 需要奇数长度与单字节读写 |
| P4-D5 | 钩子契约（写进 `PlcClientBase` 的 XML 注释表格）：字钩子仍为 abstract，所有协议都要实现（类型化读写走 `ReadAsync`）；读位钩子改为 virtual，默认抛 `InvalidOperationException`，只有软元件表含位软元件的协议需要覆写；写位钩子仍为 abstract；字节钩子为 virtual，默认抛 `InvalidOperationException`，软元件表含字节软元件的协议必须覆写。默认实现抛出的异常由流水线收口为 `Unspecified` 并记 Error（现有 `GuardAsync`）。`CanWriteBitsNatively(address)` 为 virtual，默认等于 `address.Unit == PlcAddressUnit.Bit` | 不让 S7、FINS 为用不到的钩子写死代码；MELSEC 的覆写不受影响（abstract 改为 virtual 对派生类不是破坏性变更） |
| P4-D6 | 位访问的路由：<br>• 读位：位软元件走读位钩子（不变）；字软元件读覆盖的字再取位（不变）；**字节软元件读覆盖的字节再取位**，点 i 在第 `(start + i) / 8` 个字节的第 `(start + i) % 8` 位，位 0 是字节的最低位。<br>• 写位：`CanWriteBitsNatively` 为 true 时走写位钩子，偏移按点计，协议用"地址的编号与位号（没有位号视为 0）+ 偏移"计算绝对位置；为 false 时，字软元件按现有规则读-改-写或返回 `NotSupported`，字节软元件返回 `NotSupported`（不为字节软元件实现读-改-写，YAGNI） | S7 的字节内位序与字内位序不同（大端字的位 0 在第二个字节）；FINS 字软元件支持原生位写入（位区代码） |
| P4-D7 | 字符串（用户决定"套件通用 + 协议格式"）。P2 已有 `ReadStringAsync` / `WriteStringAsync`，本期改为基于字节访问：<br>• `ReadStringAsync(address, byteLength)` 改用 `ReadBytesAsync`，结果在字软元件上与 P2 相同。<br>• `WriteStringAsync(address, value)`：字与位软元件在奇数长度时补一个 0x00（P2 行为不变），字节软元件精确写入编码后的字节（不补 0）。<br>• 新增 `WriteStringAsync(address, value, byteLength)`：固定长度字段，编码后超过 `byteLength` 返回 `InvalidRequest`，不足时用 0x00 补满，用来清掉旧的长字符串的残留字符；字与位软元件要求 `byteLength` 为偶数。<br>• 新增 `ReadByteAsync` / `WriteByteAsync`。<br>• S7 的 `String` / `WString` 格式在 Siemens 包中，是 `S7Client` 的扩展方法 | P2 已有通用字符串；短字符串覆盖长字符串留下残留字符是现场常见缺陷 |
| P4-D8 | S7 与 FINS 都用 **`CorrelationMode.Sequential`**，不用 Keyed。应答解码时校验 S7 的 PDU 引用号、FINS 的 SID 与命令码回显，不一致返回 `ProtocolViolation` | 握手帧（COTP CR/CC、FINS 节点地址请求）没有关联键，Keyed 模式下 `RequestAsync` 会以 `InvalidRequest` 拒绝；套件的操作锁本来就串行；TCP 字节流在 Sequential 请求超时后会重建连接并重新握手 |
| P4-D9 | 握手走 `ChannelComponents.Initializer`（`IConnectionInitializer`），每次重连都会重新执行。<br>• S7：COTP CR → CC → Setup Communication → 得到协商的 PDU 长度。<br>• FINS：节点地址请求 → 得到客户端节点号与服务端节点号。<br>握手结果写入一个**会话状态对象**，由 `Create` 创建并同时交给初始化器与客户端。会话状态以不可变快照保存，用 `Volatile` 替换整个引用，钩子读取当前快照 | 钩子运行时需要协商结果；重连后结果可能变化（FINS 自动分配的节点号） |
| P4-D10 | S7 与 FINS **不提供**"接收通道"的公开构造函数，也不提供公开的协议配置类，这一点与 MELSEC 不同。创建入口只有 `Create(IChannelConfig, options, loggerFactory)` 与 `Create(IChannelConfig, IChannelCreator, options, loggerFactory)`。<br>• 内置创建器只有 `TcpClientChannelCreator`，其他配置类型由 `CreatorCatalog` 抛 `NotSupportedException`。<br>• 自定义创建器的 `Delivery` 必须是 `Stream`，否则抛 `ArgumentException`。<br>• 构造失败时释放通道（与 `McClient.Create` 相同） | 会话状态把初始化器和客户端绑在一起，分开创建会出错；公开面更小（Q4）；沿用 P2.5 单一入口 |
| P4-D11 | 数据格式：S7 默认 `ABCD` + ASCII；FINS 默认 `CDAB` + ASCII（欧姆龙的 32 位数低字在前，每个字大端）。规范化布局等于设备内存的字节顺序：S7 按字节，FINS 按大端字。选项 `DataFormat` 为 `PlcDataFormat?`，null 时使用协议默认值（与 `McClientOptions` 一致） | 套件按 `WordOrder` 转换（`ByteTransform`）；对 16 位数，`ABCD` / `CDAB` 是大端，取位也正确；FINS 字符串首字符在字的高字节，按内存顺序取字节即可得到正确文本 |
| P4-D12 | 单包上限：<br>• S7 读取字节数 = 协商 PDU − 18，写入字节数 = 协商 PDU − 28。PDU 长度从 S7 头开始计，不含 TPKT 与 COTP。字数取字节数的一半向下取整。写位每个请求 1 位（单项）。<br>• FINS 读 999 字 / 999 位，写 996 字 / 996 位，由 FINS 帧 2012 字节上限推得，写入取保守值。<br>每个请求只含 1 个项 | 读：应答头 12 + 参数 2 + 数据项头 4；写：请求头 10 + 参数 14 + 数据项头 4；单项请求简单、可预测 |
| P4-D13 | S7 请求的 PDU 长度固定为 960，使用 PLC 应答协商出的值。协商结果小于 64 时握手失败，返回 `ProtocolViolation`。不提供选项 | 1200 应答 240，1500 应答 960；YAGNI |
| P4-D14 | 错误映射（只保留原始码，消息格式固定；名称表只用第 17.3 节列出的码，不编造说明）：<br>• S7 应答头的错误类与错误码非 0：`RemoteError`，`ProtocolErrorCode = class << 8 \| code`。<br>• S7 数据项返回码不是 0xFF：`RemoteError`，`ProtocolErrorCode` = 返回码。<br>• 错误为 0x8104，或返回码为 0x03、0x05、0x0A 时，消息末尾附加："Check that PUT/GET access is permitted in the CPU protection settings and that the data block does not use optimized block access."<br>• FINS 结束码先屏蔽标志位（主码 & 0x7F，子码 & 0x3F）：结果为 0 表示成功（原码含标志位时记 Debug）；否则为 `RemoteError`，`ProtocolErrorCode` 取屏蔽后的码，消息格式为 `FINS end code 0x1103.`。<br>• FINS/TCP 头的错误码非 0：`RemoteError`，`ProtocolErrorCode` 取该码 | P2-D12 的原则；1200/1500 最常见的现场问题就是没开 PUT/GET、DB 使用了优化块访问；FINS 结束码的第 2 字节最高两位是 CPU 状态标志，置位时命令仍然成功 |
| P4-D15 | 心跳探测（`HealthProbeFactory`，只在通道配置启用心跳时使用）：S7 读 MB0 的 1 字节；FINS 读 D0 的 1 字。只要收到格式正确的应答（任何返回码或结束码）就判为健康 | 复用读请求编码；PLC 回了话就说明链路与协议栈正常 |
| P4-D16 | 地址语法：<br>• **S7**：自写 `S7AddressParser`，因为 DB 地址带两个数字，声明式解析器表达不了，记入摩擦记录。<br>　- 大小写不敏感，可带 `%` 前缀。<br>　- DB 区：`DB{n}.DBX{b}.{bit}`、`DB{n}.DBB{b}`、`DB{n}.DBW{b}`、`DB{n}.DBD{b}`。<br>　- M 区：`M{b}.{bit}`、`MB{b}`、`MW{b}`、`MD{b}`。<br>　- I 区：`I{b}.{bit}`、`IB`、`IW`、`ID`。Q 区：`Q{b}.{bit}`、`QB`、`QW`、`QD`。<br>　- 取值范围：DB 号 1–65535，字节号 0–2097151（S7 的 3 字节位地址上限），位号 0–7。<br>　- 宽度字母 W、D 不限制读写长度，长度由调用的方法决定；X 必须带位号；B、W、D 不能带位号。<br>• **FINS**：用套件的 `PlcAddressParser`，位号进制为 10。<br>　- 软元件：`D`、`CIO`、`W`、`H`、`A`、`E0_`–`EC_`（EM 存储区第 0–C 组，组号为十六进制一位）。<br>　- 字号 0–65535，超出 PLC 实际范围由结束码返回；位号 0–15，例如 `W10.03` | 现场写法；PLC 的实际范围因型号不同，由设备判定 |
| P4-D17 | S7 的 PDU 引用号（16 位）与 FINS 的 SID（8 位）都来自进程级单调计数器，客户端请求与心跳探测共用 | 与 P2-D11 相同的理由 |
| P4-D18 | FINS 选项：`ClientNode`（默认 0，表示由握手自动分配）、`DestinationNetwork`（DNA，默认 0）、`DestinationUnit`（DA2，默认 0）。SNA 与 SA2 固定为 0；DA1 取握手得到的服务端节点号，SA1 取客户端节点号 | 本地网络直连的常见配置；保留路由所需的两项 |
| P4-D19 | S7 选项：`Rack`（默认 0）、`Slot`（默认 1；1200/1500 接受 0 或 1）、`ConnectionType`（PG = 1，默认；OP = 2；Basic = 3）。本地 TSAP 为 0x0100，远端 TSAP = `(ConnectionType << 8) \| (Rack << 5 \| Slot)` | Snap7 的约定 |
| P4-D20 | 已知不确定项，在代码注释与 README 中写明"未经真机验证"：<br>① 0x8104 对应"PUT/GET 未开启"是社区经验，不是官方文档；<br>② S7 写入上限 PDU − 28 是按字段推导的（Snap7 使用更保守的 − 35）；<br>③ FINS 写入上限 996；<br>④ EM 存储区组的区域代码（字 0xA0 + 组号，位 0x20 + 组号）；<br>⑤ 结束码标志位的屏蔽规则；<br>⑥ 固定客户端节点号时的握手应答 | 诚实记录，留待真机验证 |

### 11. Task 7：S7 协议层（纯字节）

内部类型放在 `Protocol/` 下。名称由执行者决定，必须体现职责，例如 `Tpkt`、`CotpFrames`、`S7Header`、`S7SetupCommunication`、`S7ReadVar`、`S7WriteVar`、`S7ReturnCodes`。
